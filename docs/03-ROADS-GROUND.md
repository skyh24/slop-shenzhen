# 03 道路与地面

## 目标

一期范围里能开车走完深南大道、滨海大道（地面段）、沙河西路、科苑大道、后海大道、福华路、益田路、金田路、彩田路、新洲路、香蜜湖路、红荔路、莲花路，车流按真实单双向和车道数行驶，路口有信号灯和人行横道。

## 路网

### 当前实现（2026-11-10 核对代码）

| 内容 | 模块 |
| --- | --- |
| 路面网格 | `js/sz-roads.js` 的 `buildSzRoads`，按源数据分块，一个共享沥青材质 |
| 标线 | `js/sz-road-markings.js` 生成布局，`js/sz-road-paint.js` 负责虚线着色和 600 m 分块 |
| 路口信号、路侧设施 | `js/sz-road-frontage.js`、`js/sz-intersection-control.js` |
| 车流路网 | `js/sz-traffic.js` 的 `createTrafficGraph`，只用地面道路（`isGroundRoad`） |
| 高架和匝道 | `js/sz-elevated-roads.js`，车公庙 37 条链路，层高按 `layer` 估计，显示和接触共用三角面 |
| 地形和派生路面 | `js/sz-ground.js`、`js/sz-ground-surface.js`、`js/sz-terrain.js`，数据由 `tools/sz/road_surface.py` 和 `tools/sz/terrain_surface.py` 生成 |

纽约的 `road-network.js` 和 `road-paint.js` 不在正式入口里，计划从 `js/` 删除，见 [22-OPTIMIZATION-REVIEW.md](22-OPTIMIZATION-REVIEW.md)。路面材质的改进方向也写在那份文档的 V1。

城区平坦基准、商圈铺装、深南中央绿带和标线标准见 [23 号](23-BUILDING-AND-STREET-PLAN.md)。正式包在一期普通城区使用 8 米工程地坪，核实的山地、丘陵公园和立交接点保留相应高程。高程来源和保留范围见 [城区基准清单](../data/source/urban-datum.json)，构建报告把派生地坪标为 `urban-datum`。

派生路面规则（`tools/sz/road_surface.py`，原写在已删除的 15 号评审第 3.1 节，是公开、可复现的估计，不是实测）：

- 基线取 `min(FABDEM 中值滤波, 原 DSM)`，只降不升，逐顶点上限为原 DSM +0.5 m。
- 共享路网节点取中值；纵坡按道路等级限制在 6–10%；横向按路宽做平的横断面。
- 路面外侧有平台和 15–45 m 的过渡带接回原地形；桥隧按 OSM `bridge`、`tunnel` 单独处理，不参与平滑；春茧等排除区受保护。
- 构建报告列出每段的派生前后高差。拿到工程标高后逐段替换。
- `build.py` 在上述派生路面基础上统一普通城区。普通公园在园内接坡，核实的山地和丘陵公园用更长的山脚过渡。三处立交及香蜜湖国际交流中心场地沿用上一版接触高程。过渡带统计包括山体边坡，通行坡度按实际路线核对。
- `build.py --rebuild-ground` 从已校验的城市包重建地形格点和地面三角面，同时生成 JSON 与 SZC1。路网和海面沿用基线，路面渲染和接触从同一份地面三角面采样。
- 沥青用均匀哑光色和场景照明，黄白标线保留真实线型及远距滤波。

以下纽约路网与按宽度推算车道的条目为早期方案；正式实施以本文末尾“用户画面反馈与优化验收”为准。车道数不能仅由宽度阈值推断并冒充真实值。

- 改动点
  - `onLand(x, z)`：改用 `city-config.js` 的 `isOnLand`，查海岸多边形
  - 主路判断正则 `MAJOR`：改为匹配“大道|快速|干道”，以及宽度大于等于 14 米
  - 车道偏移表沿用：宽度一半大于等于 10 米时五车道，8.5 米时四车道，6.8 米时三车道，4.4 米时两车道
- 信号灯周期沿用纽约 60 秒一周期：主路 26 秒变黄、30 秒变红，支路 56 秒变黄，行人绿灯 7 秒

## 用户画面反馈与优化验收（2026-11-09）

![用户提供的道路与建筑衔接截图](qa/user-feedback/2026-11-09-road-building-interface.png)

**证据范围**：截图可见道路呈缺少标线和断面层次的深色带，局部折角和地面高差突兀，建筑底部与大片铺地衔接生硬，缺少清楚的人行道、路缘和入口过渡。截图没有位置、朝向记录，不能直接认定画面就是深南大道或某一座立交。用户另明确指出深南大道主干路与立交表现不足，应作为重点实景对照对象。以下均为待实施/待验证项，不是完成记录。

### P0：道路断面与双向分幅

- 将用户所说“双车道”作为双向道路组织还原需求，核实是否分幅、每个方向实际车道数、中央隔离带、辅路与匝道；不得把所有道路统一建成双向各一车道。
- 优先使用有来源的 `lanes`、`lanes:forward/backward`、`oneway`、`width` 和独立单向道路几何，结合公开航拍/实景核对；缺失值标为推算。两个相邻单向道路不能各自重复套用整条大道总宽度。
- 深南大道按实际路段分别建断面；有证据的中央绿化隔离带、两侧绿化带、辅路、慢行空间独立生成，不能将所有中心线简单加宽并集成一大片沥青。
- 车道线、停止线、导向箭头、斑马线、分流鼻端与交通岛跟随实际路口组织；公交专用道只在核实的路段添加。车流车道中心、路面显示和玩家可通行范围来自同一份断面几何。

### P0：道路、建筑与地面衔接

- 分清机动车道、路缘、人行道、建筑退界、入口广场与绿地，不能把“陆地减道路”全部当成人行道。建筑临街面和入口应与步行网络接通。
- 保留真实建筑足迹及裙房；不通过移动建筑、任意缩楼或扩大道路来遮掩冲突。检查道路穿裙房、道路与建筑重叠、悬空底边、埋入口和不明高台，逐项回溯源数据或高程来源。
- 道路纵坡与建筑基底必须核对适用的裸地/道路标高，不能直接把 DSM 中楼顶或树冠起伏当路面。不得为平滑视觉随意归零、削坡或整栋下沉。
- 如实际存在台阶、坡道、挡墙、下沉广场或架空层，应按来源建出过渡，并使显示与碰撞一致；无证据不自动补造工程结构。

### P0：立交空间层次与可通行性

- 重点核对深南大道相关的车公庙、竹子林、深南广深立交，再扩展本文已有一期清单；根据 OSM 身份确认具体名称与位置，不能把不同立交混为一处。
- 保留主线、辅路、匝道的独立拓扑和上下层关系。`layer` 是相对层次，不是米制高度；桥面标高、净空、坡道起终点应另找证据，估算必须明确标记，不能以 `layer × 固定米数` 冒充真实。
- 显示桥面厚度、连续护栏、桥墩和桥下空间；道路与桥接缝必须连续，不得存在视觉连通而碰撞断裂、桥下被全高碰撞盒封死等问题。
- 缺少标高时应记录未完成，继续查资料；暂时不显示桥隧不能作为立交需求的最终交付。

### P1：恢复街道质感与尺度

- 以真实道路断面和建筑体量为先，再补路缘、分隔带、路灯、树列、公交站及入口细节；位置密度按道路资料/实景确认，不用随机街具填满空白。
- 借鉴纽约的沥青与铺装材质区分、建筑底层入口/商铺、玻璃与实体墙材质差异、接触阴影；先解决道路断面与建筑接地问题，不能只加泛光、反射或纹理掩盖几何缺陷。
- 近处保留车道和街道细节，远处使用合批、实例化及细节分级。新增细节需按 `10-PERF-QA.md` 同时测量性能。

### 验收方式

1. 选定深南大道普通路段、主要交叉口和立交各至少一处，记录坐标、朝向、资料日期和来源，将同位置地面视角及俯视截图与公开实景并排核对；不以不明位置截图替代。
2. 双向各走一遍核对车道数、行车方向、隔离带与辅路；车流不能穿隔离带、逆行或从断开的匝道跳到另一层。
3. 步行从人行道到建筑入口，再驾驶完成“地面道路—匝道—桥面—地面道路”闭环；检查接缝、净空、碰撞和地面接触。具体路线先依据真实拓扑确认，不能强连文档中的地名。
4. 对典型高差点记录显示顶点、接触采样与高程来源。代码同面仅证明显示/碰撞一致，不等于高程真实。
5. 保存普通游玩界面下的日间/夜间截图及帧率、绘制调用统计；结束后恢复正常游玩状态。自动模拟与人工操作的证据分别标明。
