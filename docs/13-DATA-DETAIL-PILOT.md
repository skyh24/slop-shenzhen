# 13 新数据源与城市细节小范围验证

日期：2026-11-09。状态：已做首批来源样本和局部接入，完整样区与入口/性能验收未完成；见[试点实测](qa/urban-detail-pilot/README.md)及[当前交接](HANDOFF.md)。用户授权先详细规划，再由主线程尝试小范围执行；本文不代表数据已全部取得或功能已完成。

## 1. 目标与边界

用可追溯的数据，让普通建筑、道路、树木、公园与地标周边更像真实深圳。先解决地面、建筑和交通的空间关系，再加窗户、屋顶和街具。沿用[12号协同规划](12-URBAN-FABRIC-PLAN.md)，尤其第11节道路与场地异常隆起治理。

首轮要回答四件事：

1. 新来源具体补足哪些字段，哪些只是现有OSM或Copernicus的同源加工？
2. 一个真实街区能否从“统一直筒楼”变成有用途、塔裙、入口和环境关系的街区？
3. 一段道路及一处立交的断线属于源数据、转换、路面生成还是接触/车辆逻辑问题？
4. 新细节是否在正式浏览器可见、实际可通行，而且仍满足性能预算？

不整城换数据、不整城压平、不为试点改原点，不修改只读参考仓库。当前原点和一米单位沿用CONVENTIONS。新内容通过现有管线接入，运行时不请求外部地理服务，生成文件只由 `tools/sz/build.py` 产出。

## 4. 数据契约与冲突处理

### 4.1 字段级溯源

沿用现有来源清单和审核表，避免重复发明第二套全城格式。新增样区登记至少含：

- `pilotId`、对象源ID、父部件ID、几何范围、来源链接/数据集版本、下载时间、内容日期、哈希。
- 平面坐标系统、单位、垂直基准；未知用明确未知值，不能默认为WGS84或零米。
- `evidenceType`：实测、源标签、设计、遥感模型预测、人工影像判读、程序化外观分别记录；这是建议分类，执行时映射到现有字段。
- 逐属性来源：高度、最低高度、层数、用途、年代、屋面、入口、树点、树种、冠幅、道路宽度各有出处；不得用一个“真实数据”标签覆盖全部属性。
- 图纸页码/图号、标注含义、匹配方法、冲突、审核结论、尚未解决项及允许用于显示/通行的范围。

### 4.2 几何与年代匹配

1. 先按源ID或明确的父子关系绑定；跨源匹配结合重叠比例、形状、方向、名称、部件和年代。中心点最近只用于候选检索。
2. 影像中屋顶投影和地面足迹可能不同；不能无条件把屋顶外轮廓当墙脚。
3. 总高度、层数、相对最低高度、地面绝对高程分别保存。用层数换算高度仍是估计，不改已有可靠米制高度。
4. 资料时间晚不自动优先：最新规划与较旧已竣工测绘并不描述同一状态。项目要求按建好形态展示的特定地块继续保留 `design`。
5. 图纸识别必须看图例和尺寸线。比例尺、道路宽度、图例示例不能误读为现场标高；扫描图需配准并记录残差，至少有独立校核点，不靠单点平移对齐。
6. 新证据有冲突时隔离，不为了提高覆盖率强配。未经核实的CMAB用途只能作为候选，不能把全部低楼归为别墅或城中村。

## 6. 分阶段执行

### 阶段0：锁定基线与工作归属

- 主线程审核本计划与当前任务的重复处，已有成果直接引用。
- 记录当前代码版本和未提交状态、数据哈希、浏览器/设备/分辨率、样区对象ID、相机位置/朝向、时间、交通数量。
- 对A、B、C分别保存一张地面和一张斜俯视基线；记录源数据缺失、突起、楼体错误、入口阻挡、树木穿模，给每个缺陷稳定编号。
- 保留全城包和样区对象级差异基线；主线程安排构建时点，避免多路同时重建共享包、改公共接口或控制同一浏览器。

### 阶段1：获取最小样本并判断是否有价值

1. 复用已有高程候选文件和官方目录审核，不重新下载全球产品。
2. Overture仅查询样区building_part及交通segment/connector；锁定版本，拉齐引用的父对象、连接点和必要上下游边，避免裁切人为制造断线。
3. CMAB先看目录、README、字段与许可。优先广东/深圳可分片文件；若只提供多GB归档且无法小范围读取，记录成本和替代路径，首轮先用现有OSM用途和官方总图，不让整个试点等待大下载。
4. 每个建筑样区获取1–2份相关公开总图或竣工资料及可核验实景。设计图只用于允许的设计状态或候选结构，不能升级为竣工证据。
5. 城市开放数据逐项核实当前可获取条目，保存少量样本；只有开放计划或需账号时记为线索/待获取，不伪造下载成功。
6. 本地测绘申请仅整理范围、目的、成果类型和缺失字段。当前授权是尝试公开来源的小范围验证，不自动提交身份材料、对外申请或购买数据；需要时由主线程向用户说明具体缺口。

产出来源清单与“采用/候选/无增量/待获取/不适用”结论。每个来源都要说明一个能改善的缺陷，不能只报文件数量。

### 阶段2：离线比较与审核

**建筑**：逐栋比较用途、层数、高度、部件和年代；统计新增有效字段数、冲突数、无法匹配数及预测字段占比。人工检查样区所有拟修改对象。已有可靠高度、足迹不得因新模型数值不同而自动覆盖。

**道路**：分别检查原始路网、转换后有向图、生成路面、接触与导航四层。断线标记为真实尽头/禁止通行/裁切边界/解析遗漏/同层接缝/未知桥隧/动态车辆阻塞等；禁止用最近点吸附修复所有断线。源数据共享连接点后仍需检查车辆访问和转向限制。

**高程**：按12号第11节提取纵横剖面、源像元质量、污染区域和可定位控制点。EGM2008与1985国家高程不能直接混用；未建立可验证转换时仅各自分析。平顺度改善不能代替独立地理准确性验证。没有可靠高程约束就保留未知，不以截图好看代替证据。

**街景**：将逐株树点、树列、植被面、球场面、设施地址分开；每类只采用其能证明的信息。地址只能生成候选位置，未经核验不直接摆设施。把树种、树高、冠幅和年代分别标来源。

### 阶段3：小范围生成与建模

- 使用现有审核表，必要时新增 `data/source/urban-detail-pilots.json` 等小型人工清单；此文件名为建议，主线程可按现有结构调整。
- 新规则受样区ID/边界控制；默认场景只接入已验收对象。离线报告和试验产物不能静默覆盖全城正式数据。
- 建筑先处理真实塔裙/架空/屋面部件，再处理窗户。办公的幕墙或窗带、住宅的阳台与设备位依据实景选型；窗行不冒充实际楼层。近处必要几何、远处材质简化，源ID固定种子。
- 小区保留栋间距离、真实入口、围墙开口、内部步道与公共空间。细节不足时保留简化，不随机补一圈围墙或球场。
- 道路以同一份断面生成铺装、标线、绿带边界和车道中心。主线、辅路、匝道各自建模；同一幅路面不能重复套用整条大道总宽。
- 有可靠工程面时替换受控范围旧地形，共享边界顶点；不要在DSM山包上盖一个可见平面，却保留旧碰撞山包。
- 立交整条“地面—上桥坡段—桥面—下桥坡段—地面”使用连续纵断面、路宽和一致的表面身份；桥下道路独立，桥墩和护栏保留真实通道。无高程依据时止于拓扑/外形候选，不宣称可通行真实桥。
- 地标按来源身份替换普通楼，地标周边绿地按地面、架空、屋顶的不同竖向区间处理，不把所有二维重叠都删除。
- 树木在真实树池或有依据的植被范围摆放；避免路口视线、入口、车道及低架空净空冲突。无实测尺寸的树保持明确外观估计。
- 球场按真实场地形状、方向、类型和入口建出标线、器械及已核实围网；标准尺寸仅用于已确认标准场地，不能把不规则社区场地强拉成标准矩形。
- 人车密度继续沿用12号第10节的模拟框架；本轮最多验证入口、步道和车道约束，不把市级总量、节假日预测或对象池数量称为本街段实测密度。

### 阶段4：正式页面验收与扩展决策

每个样区分别报告“数据里有→生成器生成→挂入场景→浏览器可见→实际接触通行一致”。失败停在哪一级就写哪一级，不用另一个样区的成功替代。

| 验收项 | 方法与通过条件 |
| --- | --- |
| 来源与范围 | 所有改动对象有字段来源；估计/设计值不冒充实测；样区外无非预期几何和属性变化 |
| 建筑真实形态 | 同视角参考与前后图核对塔裙、屋顶、层次和入口；无重复体量、填死内院或误删邻楼；外观分类不能靠改楼高实现 |
| 地面与接缝 | 检查实际几何边界、坡度和控制点残差；连续边界一致，不出现无依据台阶；数值误差阈值按量化精度制定，与测绘精度分开报告 |
| 步行 | 实际走人行道—前场—入口及一条公园路径；检查脚底接触、隐藏地形、台阶和架空层，不能只传送到终点 |
| 道路与立交 | 实际合法方向驾驶通过样段；双向道路两向均测，单向匝道不逆行验收；桥上桥下分别测试，不能掉落、穿层或强连未知表面 |
| 自动驾驶 | 地图实际选起终点，验证可达与不可达各一例；保留动态车流和两方向绿3/黄1/红4秒模拟信号，验证停止/放行/手动接管；不称为真实深圳信号配时 |
| 动态持续性 | 样段连续运行至少5分钟，记录人车数量、堵塞地点、时长与原因；不能通过删除全部环境车掩盖断线或死锁 |
| 树与球场 | 无树干占道、入口被堵、器械悬空、球场穿楼；大小树依据各自证据，已确认球场才放入场景 |
| 性能 | 同设备、1440p、相同机位时间和交通配置对比；报告帧时P50/P95、绘制调用、三角数、压缩包增量与冷启动，遵守10号预算；无法可靠测量显存则标未测 |
| 恢复 | 验收后恢复普通游玩界面、相机与参数，不留下固定调试状态 |

性能预算沿用[10号文档](10-PERF-QA.md)：冷启动15秒内可操作、地面60帧/飞行50帧以上、绘制调用1500以内、三角形600万以内、压缩运行数据25MB以内、显存1.5GB以内。若基线已经超预算，分别报告原有问题和试点增量，不能宣称通过；决定保留或降低细节前先测量瓶颈。

## 7. 建议交付与执行顺序

主线程统筹公共几何/表面接口、构建和浏览器；此侧对话只交付计划，不另启动执行代理或操作主线程浏览器。主线程可按其既有分工安排研究和建模，避免多人同时修改共享生成包。

1. **第一批必须尝试**：A街段、B办公与住宅候选、C公园/春茧现有资料对照。先提交来源增量表，再把证据最充分的一项做进正式页面并走通。
2. **第二批条件触发**：D立交取得可靠连接及高程资料后做完整通行；B/C新增部件、球场在身份和范围核实后接入。缺资料时仍交付明确断点和可继续的工作。
3. **第三批扩展**：首批视觉、通行、性能均通过后，再扩老住宅、别墅组团、新旧公园；不因一个样区成功全城套同一种风格。

建议验收目录 `docs/qa/urban-detail-pilot/`：

- `README.md`：样区、基线版本、来源采用结论、五级状态、未解决项。
- `sources.md`：实际取得/未取得来源、字段样本、许可核实与引用，原文件哈希链接。
- `objects.md`：修改对象ID、前后属性、审核理由及地图/图纸位置。
- `geometry-report.json`：由工具生成的剖面、连接关系、几何残差与范围外差异；通过build.py纳入可复现产出流程。
- 前后同机位截图、地面/斜俯视/夜景图、真实输入与自动驾驶记录、性能对照。
