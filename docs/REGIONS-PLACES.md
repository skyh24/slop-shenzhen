# 商圈与区域

## 已有内容

商圈已有通用建筑、地点名、铺装、人群密度和部分地标；这些由建筑、街景、地图等组件共同构成。购物公园/卓悦中心已有离线铺装审计，明通已有首层来源卡。地图和三维表现配置已共用包内区域边界，公共路径系统仍在逐样段接入。

| 当前入口 | 内容与边界 |
| --- | --- |
| `data/source/urban-datum.json` | 商业地坪范围与工程处理依据；不证明全区可步行 |
| `data/source/shopping-park-audit.json` | 草案街块/场所和核查对象，尚非运行时区域库 |
| `tools/sz/audit_commercial_paving.py`、`audit_shopping_park.py` | 对当前包三角面、建筑和道路做离线覆盖审计 |
| `tools/sz/shopping-park-road-surface.mjs` | 购物公园道路表面核查辅助 |
| `js/sz-streetscape.js`、`sz-ground.js` | 已有步行铺装与活动地面绘制 |
| `js/sz-city-config.js`、`sz-spatial.js`、`sz-map.js` | 已有地点配置、空间查询和地图展示 |

## 场景参数

`js/sz-scene-style.js` 的 `SCENE_STYLE` 持有 `schemaVersion: 1` 和稀疏绑定。区域类绑定用包内 `mapRegions.regions[].id`，道路绑定用源 `way/…`，铺装绑定用前场对象 ID。配置在场景装配时校验，缺字段采用模块默认，显式 `0` 和 `false` 按字段约束生效。`maxSlopeRatio: null` 表示没有配置坡比上限。

| 目标 | 已接参数 | 类型、默认值与用途 |
| --- | --- | --- |
| 地理区域、山区、公园、已有铺装对象 | `surfaceStyle` | 从 `SURFACE_STYLES` 选用。中心二路前场缺省暖色石材，莲花山缺省山顶石材，路侧缺省水泥。材质只应用到既有铺装对象。 |
| 公园、山区 | `fixtureSpacingM`、`fixtureSetbackM`、`maxSlopeRatio` | 间距 1–200 米，退距 0–25 米，坡比 0–3 或 `null`。人才公园沿既有路径使用 17 米、3.6 米、`null`。水体、车道、既有步行面、建筑和观景净空检查先于放置。 |
| 道路 | `lampSpacingM`、`lampsEnabled` | 间距 6–200 米，缺省由道路等级决定，`false` 关闭灯位生成。中心二路 `way/853286944` 使用 46 米。 |

每个字段先取类型默认，已核归属优先。按坐标命中时同字段按山地、公园、地理区域依次选择，同级异值冲突记一次并回退默认。对象显式配置最后覆盖。已有路径、车道、坡度、表面层级和开放权限继续由原拥有者校验。铺装沿现有对象分段，路灯沿源边布置并沿用重复坐标排除，路网和标线不因区域边界切段。

添加区域时，在 `bindings` 引用已有边界 ID 并选择预设。添加铺装外观时，在 `SURFACE_STYLES` 增加配色和米制拼缝参数，供既有对象引用。若没有可用公共铺装面，边界绑定本身不会生成地面。全区域地坪、入口与通行网络的工作见 [T4](TASKS.md#t4-区域与商圈)。

## 区域风貌的数量与布置

优先固定有来源的静态位置。人和车沿可用网络流动，由区域控制活跃度、由全局对象池控制开销。少量展示点可以配置固定目标数，目标数仍受空间容量限制。公开人口和客流保留在资料卡，模拟参数独立标注。

| 对象 | 默认规则 | 适合手工指定的范围 |
| --- | --- | --- |
| 建筑 | 用真实足迹和已知高度。仅当现有楼高需要走通用估高时，按区域、用途和部件选择合理的相对高度范围，用楼栋稳定 ID 生成可复现估计，保留 `heightSource=estimate`。用同类可靠样本的分位数定范围，记录样本数；样本不足沿用现有估算。村屋、住宅塔楼和商业裙房各用自己的范围。 | 单栋有同口径证据时走 T9 更新。一个商圈的范围可以约束缺高建筑的估计，设计限高或风貌模板不改写已有高度，也不凭区域补造楼栋。 |
| 行人 | 按可走路径的有效长度、净宽和场所活跃度加权，商场出入口和广场高一些，窄巷和普通支路受容量限制；公园步道与草坪分开。保留一套近玩家人群池。 | 有明确范围的广场或演示可设模拟人数上限。区域内无合格路径时目标为零，净宽未知时沿用保守容量。 |
| 树木 | 核实点或树列先占位。沿道路只在可种植带按间距排，公园只在允许种植的子面按有效面积和固定种子补树，保留开放草坪。生成结果随包保存，刷新、载入和远近切换复用同一坐标。树位、树种和尺寸各自记录来源。 | 地标树、入口树列和有图纸的花池逐点绑定。样板可设模拟补种上限，避开连续净通行带、斑马线、入口、车道和水体，按实际层级核桥下净空。合法位置不足时少种。 |
| 道路与环境车 | 道路条数、车道和转向来自路网。先沿用 30 辆环境车池，按道路等级、合法方向上的可用车道长度和车距对已有出生点加权，经过原有净空、路线和信号检查。区域可以让主路更活跃、支路更安静，车辆跨区继续走。 | 用路段或走廊权重控制生成分布。验收回放可以固定初始目标数，日常仍按可用路线放车。灯杆或行道树等静态设施沿合适断面按间距布置。 |

### 首个样段

1. **选购物公园/卓悦中心一段已经核对的公共路径和相邻道路。** 复用 R1 的场所 ID 和边界。沿实际步行线、种植带和有向道路取样。区域有重叠时，同一位置同一类配置只用一个有效覆盖，由明确的子范围优先。地图可同时展示多个场所关系，生成预算只计算一次。
2. **静态配置离线生效。** 树按固定点、树列、规则补点的顺序处理，ID 用稳定的种植带/路段、侧别和槽位，公园补点用稳定网格。相同输入重复生成的楼高、树位及树 ID 应一致，改变一个区域配置后检查范围外数据差异。楼高和树位交给既有渲染与碰撞消费。
3. **动态配置在现有调度里生效。** 行人优先复用 `densityAt`。若场所禁止或无证据支持进入，须从合格路径和容量里排除，单设密度为零仍会触发现有最低活跃度和最低人数规则。车辆只给已有出生候选加权，维持原有线路方向、分层、信号、车距与镜头内连续性。跨区时只渐进调整生成和回收，不重置现有实体。昼夜变化等样板通过后再调。
4. **可见效果和通行一起验。** 在同一存档与视角比较商圈与支路，记录树位来源、行人/车目标与实际活跃数、空间不足的拒绝原因、包增量和帧时。实际往返 200–400 米，至少跨一次区域边界，检查树和灯后的连续净通行带、行人队列、车辆跨区以及树木刷新稳定性。道路专项的通行面与绕障职责见 [32 号第 10 节](32-ROAD-NETWORK-AND-STREET-PLAN.md#10-人行道树灯挡路与浅色空地补充核查)。

## 验证与参考

离线审计核实际三角面及车行范围；二维建筑投影不等于扣除了柱廊/架空层后的公共面积。旧面积报告须用当前包复核。运行时改动按所属组件选择 `data/roads/street/ui`，接触变化加 `controls`；最终以一条有来源的商圈公共路径实走验收。

基础实现分别见 [建筑](04-BUILDINGS.md)、[道路](03-ROADS-GROUND.md)、[街景](06-STREETSCAPE.md)、[地图](09-UI-GAMEPLAY.md)。调研取舍见 [RESEARCH](RESEARCH.md)，后续地点扩展仍在TASKS T11/T14。
