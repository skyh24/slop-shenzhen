## 1. 纽约经验及深圳取舍

以下是本地参考代码的复核结论，不是对纽约全城精度的背书。

| 主题 | 纽约的实际做法 | 深圳采用方式与限制 |
| --- | --- | --- |
| 普通建筑 | [buildings.js](../ref/slop-newyork/js/buildings.js) 保留源轮廓、楼高和年代；按年代及位置种子选择五类立面，另生成商铺、檐口、设备等 | 保留真实几何，区分建筑用途、群体类型和外观。缺用途或年代时不能用概率生成结果反写成事实 |
| 建筑细节 | [building-details.js](../ref/slop-newyork/js/building-details.js) 检查相邻楼体与预留空间，再放雨棚、设备等；近处加载 | 迁移邻近避让、分块和流式细节；不照搬纽约水塔、消防梯，不全城自动加店铺 |
| 道路与车道 | [geo-streets.mjs](../ref/slop-newyork/tools/geo-streets.mjs) 读取路宽/方向/车道标签；[road-network.js](../ref/slop-newyork/js/road-network.js) 生成可行车道；[road-paint.js](../ref/slop-newyork/js/road-paint.js) 据同一路网画标线 | 断面、标线、停车线与车流统一；纽约也有推导车道规则，不能当作深圳实测。深圳桥隧、高差和辅路需独立证据 |
| 树木 | [build-trees.py](../ref/slop-newyork/tools/build-trees.py) 使用市政树点；[tree-placements.js](../ref/slop-newyork/js/tree-placements.js) 有小幅路缘适配；[city-grid.js](../ref/slop-newyork/js/city-grid.js) 在公园允许区域生成树群 | 深圳先源点、后有证据的树列/植被面。若显示点位发生调整，保留源位置和位移，不静默挪树或称为实测 |
| 行人 | [pedestrian-routes.js](../ref/slop-newyork/js/pedestrian-routes.js) 建人行道/过街连接；[pedestrian-system.js](../ref/slop-newyork/js/pedestrian-system.js) 在附近模拟人群、信号等待、排队和避让 | 复用路线与行为思路，改接深圳真实步行网络和表面高程；人数、活动与时段均为模拟，随机过程改用实体固定种子 |
| 地标 | [landmarks.js](../ref/slop-newyork/js/landmarks.js) 将专属模型拟合至地块；普通建筑生成时排除重叠对象 | 按已核实源 ID 及部件绑定替换，保留真实邻楼；地标显示、碰撞和可通行面同源，不照搬整体矩形碰撞盒 |

## 2. 真实性与共同数据契约

将“几何来源”“高度来源”“外观判断”“模拟行为”分开记录。下列为拟增加的字段或等价结构，接入前检查现有格式，不代表运行包已经具备：

| 内容 | 拟记录信息 | 缺失时处理 |
| --- | --- | --- |
| 建筑与场地 | `sourceIds`、`parentId`、用途、部件角色、群体/小区关联、入口、资料日期 | 缺群体边界不凭距离合并小区；缺用途保持未知 |
| 建筑外观 | `appearanceClass`、`appearanceSource`、年代/改造证据、配色和细节规则版本 | 可使用中性或片区先验外观，标 `inferred`；不伪造建成年份 |
| 道路断面 | 主辅路身份、方向、车道及宽度来源、慢行空间、表面/高程来源 | 缺值与规则推导值分开；未知桥隧标高不作为可通行连接 |
| 树木 | 源点/树列/植被面、树高/胸径/冠幅/树种各自来源、源位置与显示位移 | 可估外观但不能把树高、树龄、种类写成实测；无依据的点不声称真实树位 |
| 公园 | 真实边界、入口、开放通路、水岸、建成/改造时间、植被成熟度证据 | 新旧程度与树龄独立；未知时间不猜具体年份 |
| 人群 | 可行走表面和路径、活动区域、密度配置、种子 | 明确模拟人数与活动，不冒充实时客流 |

新增来源放 `data/source/`，原始文件放 `data/raw/` 并锁定哈希；生成内容只经 `tools/sz/build.py`。不为美化改动源 DEM、楼高、真实足迹。DSM 的屋顶和树冠回波不能直接解释为地面，冲突保留证据并查更合适的地面/工程资料。

## 3. 普通建筑与小区：先分空间类型，再分外观

原有六类立面是材质库，不足以表达所有城市形态。改为“建筑用途 + 单体/群体类型 + 建筑部件 + 年代/改造外观”组合，避免同一种玻璃材质套遍办公和住宅，也避免把整座小区挤成一个大盒子。

### 3.1 类型与模型规则

| 类型 | 需还原的体量与场地 | 外观重点与限制 |
| --- | --- | --- |
| 一般写字楼 | 源塔楼/裙房、办公入口、前场、车行落客与服务入口 | 玻璃或实体窗墙、层间带、机电层；不能因楼高就判为玻璃办公楼 |
| 园区办公、研发楼 | 多栋低中层楼、真实院落、步行连接、围合边界 | 横向窗带、遮阳、入口雨棚；园区不自动视为公众可通行 |
| 老居民楼小区 | 板楼/点楼、单元入口、楼间路、停车及公共院落 | 阳台、空调位、栏杆和屋顶设备按证据；老楼不统一做脏旧或破损 |
| 现代高层小区 | 各栋真实塔楼及住宅裙房、花园、围墙/门岗、人车入口 | 住宅窗墙比例、阳台/飘窗、设备位；楼间距和朝向沿用源数据，不随机排塔楼 |
| 别墅群、低密住宅 | 独栋/联排类型、每栋足迹、独立庭院、组团道路、围墙和出入口 | 屋顶形态、露台、车库等逐项核实；低矮建筑不能仅凭面积自动判为别墅，不能在真实楼间补造住宅 |
| 城中村及紧密街巷住宅 | 独立楼栋、窄巷、骑楼或底层架空的实际范围 | 密窗、瓷砖/涂料、空调位、底商；不随机扩雨棚堵巷，不把所有小楼归为城中村 |
| 商业与住宅/办公混合体 | 商业裙房与上部塔楼分别建，区分购物入口、住宅入口和服务通道 | 店招只落在有商业依据的临街面；没有品牌/店铺证据时使用明确的通用场景文字 |
| 公共服务及工业建筑 | 学校、医院、厂房等保留独立用途，按源足迹和专属类型处理 | 不能被住宅/办公分类强行吸收；重要公共建筑按地标或独立模板处理 |

### 3.2 判定顺序与样式差异

1. 优先使用核实的单栋用途、建筑部件、建成年代/改造资料及实景；其次使用有明确关联的小区/园区边界和用途。
2. 片区、楼高、面积只能作为外观候选的弱线索。现有“高于150米即玻璃”“小面积即城中村”等规则降为带来源说明的推断，不改变建筑用途。
3. 同一小区按证据采用一致的建筑语言，并给不同楼栋保留合理差异；固定种子由源 ID 生成，不因数据排序变化而全城换外观。门窗节奏按墙面局部坐标和层高组织，避免斜向建筑被世界坐标纹理切碎。
4. 年代、翻新与用途分开：旧小区可有新立面，新办公楼也可能采用石材。颜色/粗糙度变化用于外观表达，不能凭颜色宣称某楼的真实年龄。
5. 有源 `building:part` 时优先使用真实塔裙、退台、连桥和架空层；无部件时，不以“丰富样式”为由扩大占地。确需估计体量，另标估计并限于已知占用范围，避开道路、入口和内院。
6. 屋顶设备、空调外机、檐口和雨棚经过邻楼及通行净空检查后生成；远处减细节，不改变碰撞和主要轮廓。

## 4. 多样道路断面与建筑接壤

道路类型不是单纯换宽度。采用沿里程分段的断面，保留每段真实主线、辅路、绿化分隔、步行和骑行空间的独立关系。

| 场景 | 规划重点 |
| --- | --- |
| 深南大道 | 分段核实双向主路、辅路、中央及侧向绿带、公交/慢行设施、地铁入口；不把各条中心线都画成整条大道总宽 |
| 北环大道 | 区分快速路主线、辅路、出入口与立交；主线不任意添加平面斑马线和红绿灯 |
| 普通城市街道 | 按源方向/宽度分配车道，沿实际临街退界组织路缘、人行道和入口，不把所有剩余陆地铺成人行道 |
| 小区、园区及窄巷 | 核实公共/内部通行边界、门岗、消防/服务通道；不得把封闭小区捷径接入公共自动驾驶路线 |
| 立交及高架 | 主线、匝道、桥下、慢行连接分层；实际桥面、净空和接缝同源，`layer` 不换算成固定米数 |

统一从断面及已验证路网派生沥青边缘、车道中心、标线、停止线与交通岛。车流、自动驾驶、玩家接触及地图路线使用相同身份和方向；转向禁限、车辆包络、转弯半径与分层连通分别核查。公交专用道、箭头和路缘坡口不能凭“典型深圳样式”随处添加。

临街衔接按“车道 → 路缘 → 人行道 → 建筑退界/前场 → 实际入口”核查。路口和出入口要留连续可行走空间，植物、店招、停车单车、灯杆不能堵住入口。已确认的两组8秒信号与地图自动驾驶按03、07、09的现行要求执行，本规划不改变其时序或入口安排。

## 5. 公园、行道树与植被成熟度

### 5.1 公园不是统一草坪和等距树列

| 场景 | 应表达的区别 | 所需依据 |
| --- | --- | --- |
| 较成熟公园/老小区绿地 | 大树与小树混合、冠层重叠、林下空间、保留开敞活动场地 | 实景/航拍、树点、冠幅或树高资料；成熟不等于每棵树都大 |
| 新建或近期改造公园 | 苗木、保留大树、补植区、较开敞的冠层、更新铺装并存 | 建成/改造资料和近期照片；新公园也可保留老树，不统一画成小树 |
| 城市广场/道路绿带 | 树池、行列节奏、分隔带植被与人行通道之间的关系 | 路段景观资料、实际树列/树点与铺装边界 |
| 山地公园 | 地形、步道、林地与开敞地的不同密度，坡面接地 | 真实植被面和地形；不抬树、不压坡来填空 |
| 滨海公园/湿地 | 观景草坪、乔木区、滨海步道与保护植被分别表达 | 实际岸线、湿地与植被范围；不把整条海岸都种成红树林 |

树木分三层来源处理：①核实单株点位；②有证据的连续树列；③有证据的植被面内模拟树群。第一类保留源坐标，冲突点先报错/隔离；若必要的显示适配获采用，记录偏移量与原因。第二、三类可以使用固定种子和间距/冠幅约束，但标为程序化布置，不列为单株实测。

树高、冠幅、枝干、树种和树龄是不同属性。大树/小树优先按测量或影像尺度分级；只有大小不能推出准确树龄。缺属性时用有范围的外观估计，保留未知；不同树龄外观可有树干粗细、冠形和叶量变化，不用随机缩放一种树覆盖所有类型。榕树、木棉、凤凰木、棕榈类等只是候选模型库，具体路段种类、开花季节与密度需核实。

废止无条件“每9米一棵、路口统一留12米”的全城补树规则。间距来自可核实树列或景观段配置；安全间距作为模型检查参数，不冒充当地实际种植间距或设计规范。检查树池/树干与车道、步道、建筑、地铁口、公交站、灯杆和视距区域的冲突。冠层允许合理重叠，硬树干不能穿楼、占道；显示树干与碰撞同源，摆放避让范围单独记录。

## 6. 行人与活动

- 先生成连接实际入口、人行道、合法过街、广场和公园步道的步行网络，再放人。步行层保留高程/表面身份、通行权限和障碍；桥上桥下或不同楼层投影相交不等于连接。
- 办公区可配置通勤/午间停留；住宅小区配置出入、散步及公共活动；商业街配置浏览和结伴；公园配置散步、跑步和观景。这些是可调模拟情景，无客流证据时不标真实人数或作息。
- 人群只在允许区域中选择起终点、停留位及队列。封闭院落、未核实开放的校园/园区、湿地和车行主线不自动作为可达目的地；未建室内时不让人穿墙进入。
- 沿纽约方式在玩家附近维护可复用人群，远处降低更新和动画精度；避免视野内凭空出现、重叠和突然消失。人物外形、速度、活动用固定种子生成，数量由10号文档预算实测决定，不照抄纽约340人的常量。
- 过街共用信号相位与冲突区状态，车辆让行、行人等待及队列容量一起处理；有人未走完时不能只因切绿就让车穿过人。近处用动态碰撞及跨帧检测，避免低帧率穿透。
- 脚步与坡面、台阶、平台一致，路径逐段检测人物身体宽度和高度。小区门岗、窄巷、桥下、建筑雨棚和地标架空层要分别实走。

## 7. 地标、绿地与建筑的冲突治理

不能靠人物碰撞解决草坪穿楼，也不能靠删楼、挪树或压地形掩盖来源冲突。采用共同平面边界、垂直区间和表面身份，区分下列情况：

| 冲突 | 处理方式 |
| --- | --- |
| 地标与普通楼重复 | 由源 ID、父子部件及核实重复映射替换。地标生成成功才跳过原对象；未成功保留回退。预留区用于细节避让，不是删除所有邻楼的范围 |
| 草坪穿地面建筑 | 先核实绿地面是公园边界还是实际草坪，再按地面实体占用裁切可见草坪。保留源面与派生裁切记录，不删除公园内合法建筑 |
| 屋顶花园/平台绿化 | 作为依附具体屋面/平台的表面，不投影成地面草坪；高度、结构与接触共用来源 |
| 架空楼、连桥与地面绿地重叠 | 按真实竖向净空判断，合法上下重叠不能被二维差集误删；碰撞按分段实体保留通道 |
| 树干或街具占路/入口 | 用共享占用索引检查，记录冲突对象与原因；核实来源后决定保留、调整显示或暂不生成 |
| 道路、建筑基底与DSM冲突 | 分清相对楼高、地面绝对高程和屋顶回波；另查工程标高/裸地证据，未知项保留，不自动填造台阶、墙或坡道 |

建议生成顺序：来源绑定与高程审计 → 地标/普通建筑占用及分段实体 → 道路断面和可行表面 → 草坪/铺装派生裁切 → 入口与步行连通 → 树木和街具避让 → 行人与交通。必要时二次校验，不能仅依赖创建顺序碰巧盖住冲突。

生成报告增加类型分布、未知/估计比例、地标替换 ID、源点位移、重叠面积、垂直净空、不可达入口、跳过树点和无效路线等统计。每项保留对象 ID、位置、处理理由及可复核证据；调试层显示建筑占用、草坪裁切、树池和行走面，正常游玩默认关闭。

## 8. 分批实施与验收

| 批次 | 范围 | 交付与验收 |
| --- | --- | --- |
| A 数据及共同规则 | 类型、来源、占用/表面接口与冲突报告 | 先对已有数据做只读审计，核实所有拟新增字段；准备可重复的源对象样例，不扩大估计值为事实 |
| B 道路街区试点 | 深南大道车公庙段与一个真实信号路口、北环一个地面/立交样段 | 普通楼与临街入口、主辅路、树列和人行道一起核对；双向驾驶、步行入口、信号等待；缺桥面高程的立交不能验收为可开 |
| C 建筑类型样板 | 办公、老住宅、现代高层小区、别墅群、城中村各一处 | 先核实具体源对象和所在覆盖区；逐栋/组团对照体量、入口和外观。暂未绑定的别墅样板列缺口，不虚构地点或挪入一期 |
| D 公园及人群试点 | 深圳湾公园现有步道、市民中心公共空间；再选择有证据的新旧公园对照 | 大小树、冠层、铺装和入口对照；连续观察人群进出/停留/过街，实际穿行，验证层级和车辆让行 |
| E 扩展与性能 | 将已验收规则扩至其余一期街区和地标周边 | 按10号文档测冷启动、地面/飞行帧率、绘制调用、三角形与内存；增加细节后仍需满足预算 |

每处保存来源日期、源 ID、坐标和朝向、地面/俯视及日夜截图、冲突处理记录和实际路线。至少覆盖普通人行道进楼前场、窄巷、住宅入口、树池旁、信号过街、桥上桥下及绿地邻接地标。测试重点是源 ID 不误删、未知不变零、层级不串联、边界不穿透和确定性；不能只测“函数返回了对象”。

汇报仍按五级：数据里有 → 生成器生成 → 场景挂入 → 浏览器可见 → 实际操作且碰撞/通行一致。截图可见不等于实景准确，程序碰撞一致不等于高程真实。每批完成更新 TASKS/HANDOFF，验收后恢复普通游玩页面。

## 9. 窗户、楼层、屋顶、道路绿带与运动场追加规划

2026-11-09 用户追加。目标是在正确形态和空间关系基础上增加可辨认细节，避免只有地标精细、普通街区仍像同一批直立盒子。

### 9.1 纽约代码提供了哪些具体方法

- [building-footprints.js](../ref/slop-newyork/js/building-footprints.js) 为每段墙提供局部墙面坐标，窗格沿真实墙面方向排列；区分外墙、内院和贴邻楼的墙面，并对部分低楼检查邻楼遮住的墙高。屋顶按含内院的多边形三角化，不封住院洞。
- [tsl-materials.js](../ref/slop-newyork/js/tsl-materials.js) 的 `facadeCell` 保留墙角和屋顶实墙区域，避免不完整楼层被切成半排窗；住宅材质用视差室内、窗帘和房间亮灯变化表现纵深，远处窗灯过滤成稳定亮块以减少闪烁。玻璃幕墙另有窗框、层间带和规则化机电层。这些是外观生成，不能当作逐楼真实层数、机电层或室内数据。
- [building-details.js](../ref/slop-newyork/js/building-details.js) 在实际屋顶多边形内寻找设备位置，检查邻楼和已占用区域；临街雨棚、檐口等亦有避让。纽约式水塔和消防梯不作为深圳默认细节。
- [city-grid.js](../ref/slop-newyork/js/city-grid.js) 将中央绿化岛做成独立路缘/平台和内缩绿篱，并加入交通占用范围；不是只在沥青上画绿色线。其固定高度是纽约显示配置，深圳不直接套用为真实标高。
- 同文件 `kinds.pier40` 单独组合围合建筑、院内球场、屋顶球场、围网和灯杆；运动草皮材质在场地局部坐标画足球标线。这证明可以用少量几何和程序化材质做出功能明确的空间，但不是纽约已建立全城通用球场系统，也不是这些尺寸均为实测。

### 9.2 每栋楼的窗户和楼层

| 层次 | 深圳规划 | 验收重点 |
| --- | --- | --- |
| 楼层资料 | 保存 `building:levels`、`roof:levels`、裙房/塔楼部件层数及各自来源；地下层数与地上层分开 | 楼高、层数、屋顶高度口径一致；有冲突不静默覆盖 |
| 垂直分段 | 按证据划分首层、标准层、裙房、机电/避难层和顶层；缺资料时用带标注的立面节奏估计 | 不为凑整数层改真实总高；立面窗行数不冒充实际楼层数 |
| 平面窗格 | 沿墙面局部方向、按米制窗宽组织，保留墙角/端墙；不同立面可有不同开窗率 | 斜楼窗格不拉伸，边角不出现切半窗，贴邻墙不生成穿墙店面 |
| 办公立面 | 玻璃幕墙网格、层间带、实体核心筒/机电区、入口大厅按各楼或类型证据组合 | 不将每块幕墙玻璃当成一间房；机电层不全城固定每若干层重复 |
| 住宅立面 | 单元开间、客厅/卧室窗、阳台、飘窗、空调机位有成组逻辑 | 同一户/单元规则连贯，不把所有住宅刷成办公玻璃网格 |
| 临街与背面 | 根据实际入口、道路和用途区分大厅、底商、住宅单元入口、后勤面、内院面 | 不是四面都开店；雨棚、门洞与真实通行路径对应 |
| 夜间窗户 | 按楼栋/楼层/房间固定种子生成可配置亮灯组与窗帘变化，区分办公与住宅的模拟时段 | 不逐帧随机闪灯，不整栋同亮，不把模拟灯光称为实时占用 |

近景只对影响轮廓、遮挡和通行的阳台、雨棚、入口凹槽等使用真实几何；普通窗框和远景细节优先着色器。视差室内仅是外观，不产生可进入房间或内部碰撞。远处过滤细线和窗灯，避免摩尔纹、闪烁；近远切换不改变建筑身份和主要轮廓。

### 9.3 楼顶不是统一平盖

- 区分平屋顶、坡屋顶、退台、设备层、屋面花园、楼梯/电梯机房和地标顶冠。屋面类型取源标签、图纸或实景；别墅不一律红色坡顶，高层也不一律停机坪。
- 记录檐口/女儿墙顶、主要屋面、设备和尖顶的高度口径，避免源总高之外再重复叠加完整屋顶。缺失部件尺寸标估计，不能改变已知真实高度。
- 设备房、通风/冷却设备、光伏、楼梯间、水箱等仅在有资料或明确标记的类型化外观规则下放置；不凭空添加大型结构、停机坪或公共屋顶花园。
- 部件必须完整落在可承载的对应屋面内，避开内院、天窗、退台开口和相邻高楼。屋顶绿化依附屋面表面身份，不能落回地面高程。
- 可行走/可降落屋面另做入口、坡度、承载外观与碰撞检查；“屋顶画出来”不等于允许进入。检验俯视、街道仰视与近距离飞行三个尺度。

### 9.4 道路绿化带

分别处理中央分隔绿带、主辅路之间绿带、机非分隔绿带、路侧树带和交叉口交通岛。每段记录真实边界、宽度变化、端头、过街/转向开口与树列，不能沿所有道路自动加一条同宽绿带。

在可核实边界内组织“路缘/挡边 → 土壤或地被 → 灌木 → 乔木”的实际层次；并非每条绿带都必须四层齐全。连续绿篱使用适度变化的合批几何，乔木按来源点/树列实例化；避免长条纯绿盒子和完全等高树冠。近处补可见树池、铺装收边与维护开口，具体设施仍需来源。

绿带与车辆通行、掉头口、公交停靠、过街及无障碍连接共用边界。路缘与树干是实体，植物视觉冠层和摆放避让范围分别处理。高程接已有真实路面/景观表面，不能复制纽约固定平台高度覆盖深圳纵坡。试点至少包含深南大道一个主辅路段与北环一个分隔/匝道段，双向观察并验证不会驶穿隔离实体。

### 9.5 公园球场及活动设施

先建立运动场源对象清单，核实 `leisure=pitch`、`sport`、场地边界、方向、铺面、围栏、入口、灯杆、所在层及开放权限；用公开场地图或有日期的影像补充。点状设施不足以确认场地尺寸，不用公园空地自动填球场。缺项保留待核实，不伪造本地设施。

| 类型 | 模型组成 | 必须区分 |
| --- | --- | --- |
| 篮球场 | 场地铺面、实际标线、篮架/篮板/篮圈、围网及入口 | 全场/半场、多场并排、周边缓冲；不将所有矩形铺地识别为篮球场 |
| 网球/羽毛球等 | 对应类型标线、网柱/球网、围网及附属空间 | 室内外、单场/多场、场地类型和实测/推断尺寸 |
| 足球场 | 草皮/人工草、正确方向的标线、球门、围网 | 大小场、训练场或复合场；尺寸由来源决定，不强拉成某一标准场 |
| 跑道与综合场 | 实际跑道形态、分道线、内场和出入口 | 学校/社区/公园权限及场地层级，不能默认全开放 |
| 健身/儿童活动区 | 已确认的器械类型、铺面、围合与入口 | 不与球场共用一个通用模型，具体设备数量不足时标缺口 |

表面标线以局部米制坐标生成，尺寸从核实场地读取；资料缺失时使用明确标记的展示估计，不能宣称符合官方比赛标准。围网细节可用透明裁切材质或实例化构件，杆件、门洞和人体/车辆碰撞来自一致几何。球场原则上具有独立平整工程表面，但其绝对高程或坡度未知时不能将周边DSM任意压平；屋顶球场尤其必须核对楼体及出入关系。

第一批只选择已核实的篮球/足球等少量样板，完成场地、围栏开口及接地后，再增加打球、跑步和场边休息的模拟行为。活动区与普通穿行路径分开，行人不能随机从球门、围网或正在使用的球场中央穿过。体育动作和球的模拟另列成本，不以摆放静态人物冒充完整玩法。

### 9.6 地标与普通楼的区别及一致性

两者都需真实位置、体量来源、合理窗层、屋顶和地面关系；区别在于外观模型如何生成、验收精度和可辨识特征，不在于地标可以脱离城市环境。

| 对象 | 生成策略 | 验收要求 |
| --- | --- | --- |
| 普通楼 | 真实足迹/部件加用途、年代及类型模板；必要细节按证据或明确外观估计生成 | 街区类型、尺度和层次可信，不要求每扇未经测绘的窗都一一对应 |
| 重要邻楼/有显著特征的普通楼 | 在批量体系里加单栋外观覆盖或专属部件；不以是否在地标名单限制精度 | 避免关键天际线、街角或视线背景被通用盒子破坏 |
| 地标 | 按独立卡片和来源还原曲面、收分、退台、支撑、连桥、屋顶及立面节奏 | 从多个方向能辨认，轮廓与尺度核实；架空空间/入口/周边实际通行 |

所有模型统一米制尺度、材质色彩空间、曝光、粗糙度与日夜照明基准。地标不独立过曝、浮地或拥有不合理的亮度；普通楼也不一律用纯色平盖。城市真实性优先级为：正确布局与高程 → 类型/轮廓/屋顶 → 道路和入口衔接 → 窗层与植被尺度 → 生活活动 → 小细节和光效。每步用固定地点、朝向、时段和视场角对照，不能只靠“加更多物件”评判进步。

## 10. 行人与车辆的出现和密度

### 10.1 纽约当前代码的标准

以下数字仅指本地参考版本的普通街道系统，不能代表纽约真实流量，也不是所有远景/高速车辆的合计。[traffic.js](../ref/slop-newyork/js/traffic.js)、[pedestrian-system.js](../ref/slop-newyork/js/pedestrian-system.js)

| 参数 | 普通街道车辆 | 行人 |
| --- | --- | --- |
| 预分配数量池 | 200辆车、12辆公交 | 340人 |
| 常规补充距离 | 距活动中心100–350米 | 距活动中心60–280米 |
| 超出后可重新布置的距离 | 380米 | 320米 |
| 近视野生成保护 | 用250米近视野检查，另避开玩家25米内 | 用150米近视野检查 |
| 常规每帧重新布置预算 | 至多处理4个对象 | 至多处理6个对象 |
| 传送/大位移 | 可在0–350米重布，放宽近视野保护和本帧预算 | 可在0–350米重布，放宽近视野保护和本帧预算 |

数量池不是每个镜头必有这么多实体。生成还取决于附近可用道路/步行路径、空位、队列和视锥；失败可留待后续尝试。车辆在可用有向车道上选择位置，公交限制到系统认定的主路边，检查车身长度与车道间距；不是公交真实运营班次。行人选择已验证人行道/过街路径，路口检查队列空间。远处对象循环使用，避免全城持续模拟；常规生成保护只是减少近处突然出现，并不保证所有远景绝无跳变。

车辆跟车另用驾驶模型：小车目标时距1.2秒、静止间隙2米；公交1.5秒、2.5米。这是模型参数，不是生成密度、法律标准或实测纽约驾驶行为。红绿灯、转弯、前车和行人让行共同影响实际队列；不能把对象池数量除以圆形半径面积，称为真实道路密度。

### 10.2 深圳的密度规划

将三件事分开：①性能允许的对象池上限；②场景希望呈现的目标密度/流量；③当前位置实际可容纳的安全数量。不得只提高固定总数，使窄巷、绿地、快速路和商业街同样拥挤。

- 车辆按有效有向车道长度和路段用途分配目标数量，可用“辆/车道公里”记录；需要连续交通流的边界另设“辆/分钟”的模拟到达率，两者不可混为一项。公交单独分配，只有真实线路/班次来源才表示对应服务。
- 行人按可行走面积、有效路径长度、入口与活动节点分配，可用“人/有效步行面积”或“人/百米路径”记录，明确统计口径。办公、住宅、商圈、公园和活动情景各有配置，不根据整个地块面积填人。
- 无实测数据时提供稀疏/日常/繁忙的模拟配置，先在固定试点量测可容纳空间、冲突和性能，再确定具体数值；不给尚未校准的数字贴“真实深圳高峰”标签。新旧小区/公园外观不直接决定人数。
- 生成必须满足已验证表面、方向/权限、身体间距、入口和冲突区空位；位置不合法就少生成，不移楼、穿网或让车辆落到错误桥层来补满数量。
- 使用固定种子和基于模拟时间的补充限速，限制每帧工作量；不直接照搬纽约每帧常量造成不同帧率下补充速度不一致。近视野保护、远处回收与传送重布分别记录和验收。
- 性能下降先降低远景细节和远处更新率，再平缓调整远处目标人数；保留眼前实体、当前排队关系和碰撞连续性，不能在玩家面前突然清空交通。

验收记录目标池、实际活跃数、实际可见数、有效车道长度/步行面积、生成失败原因、排队长度与帧时；在同一位置、种子、时段和机位对比至少一段连续运行，检查红灯积队、绿灯消散、出入口拥堵及近视野突然生成。密度增加不能破坏已有通行与性能预算。

### 10.3 首版实现（2026-11-09 晚）

环境跑者（步行人群）已按本节的模拟口径接入正式入口，具体模块、参数、测试和限制见[06号文档的环境走路人群首版](06-STREETSCAPE.md#环境走路人群首版2026-11-09-晚)。首版用沿道路两侧偏移的**模拟步行带**和模拟铺装代替全城实测人行道，120 人、20–160 m 出生、220 m 回收、130 m 内解算；车辆仍是 30 辆的固定池。没有实现过街信号、排队容量和车辆让行；这些是下一轮验收项，不能把“画面里有人”当作 10.2 的密度验收通过。

## 11. P0：消除道路与建筑周边平地的异常隆起和穿模

2026-11-09 用户确认：将地面与地物分离纳入解决方案，尽量使路面、建筑周边平地不异常凸起、不穿模。此项优先于继续增加窗户、树木和街具细节；本节是待实施方案，不代表地形问题已经修复。

### 11.1 问题与目标

当前道路沿同一地形三角面裁切，源 DSM 的屋顶、树冠及粗网格插值起伏可能一起被当成路面。25米输出网格不是精细道路测绘；建筑中心或公园中心的采样值也不自动等于地面控制点。已知案例见[春茧验收卡](landmarks/chunjian.md)和[地形候选审计](qa/m2-terrain-candidates/README.md)。

目标是去掉被证据判定为地物污染或几何接缝错误的隆起，保留真实山坡、道路纵横坡、台阶、平台和下沉空间。“平地”是需核实的场地属性，不是任意画框后强制拉平；道路平顺也不等于处处水平。真实数据要求保留来源和处理过程，不要求把原始 DSM 无区别地作为最终地面。

### 11.2 数据与表面分层

| 层 | 用途 | 约束 |
| --- | --- | --- |
| 原始 DSM/其他高程源 | 可复现证据与对照 | 原文件与哈希保留，不覆盖、不改写为“裸地” |
| 自然地形 | 山体、经核实的非工程地面 | 优先合适的裸地数据；不能为道路观感压平整座山或全城归零 |
| 道路工程面 | 车行道、辅路、路口、匝道 | 以道路标高/纵横断面及可靠地面约束生成，独立于楼顶和树冠 |
| 建筑周边场地 | 人行道、广场、前场、球场、小区院落 | 根据场地边界、入口和排水/工程坡度分片；真实不同层不能合成一块平面 |
| 建筑及架空结构 | 地面实体、平台、连桥、屋顶、桥面 | 记录绝对基底与相对构件高度，保留桥下及建筑架空通道 |

坐标和垂直基准先对齐，再比较标高。工程“±0.000”“+6.0”未绑定绝对基准前，不直接与 EGM2008 或其他高程混用。设计图、竣工资料和实测资料分别标记；设计值不能称为现状实测。

### 11.3 处理流程

1. **定位异常**：按道路、入口及场地源 ID 提取纵剖面/横剖面，标出尖峰、突变、与楼顶/树冠区域重叠、地面盖住建筑和入口高差；结合影像/图纸判断，不能仅凭“看起来不平”删掉真实坡度。
2. **识别污染与有效约束**：结合建筑部件、植被范围、源像元质量和可靠裸地点筛选控制样本。考虑粗像元及插值把屋顶影响扩散到轮廓外的情况；不对全部楼统一外扩固定距离后削平。相邻像元也可能被污染，不能默认边界点都是地面。
3. **优先补足真实地面资料**：使用适用的裸地模型、本地测绘、竣工道路标高及场地工程资料。优先核查市民中心道路/平台、春茧封闭场馆周边、深南大道车公庙段及北环样段，不把同一标高外推到全城。
4. **在有约束的范围重建**：对已有可靠端点、边界和坡度依据的地面路段，建立分段纵断面与横断面；对确认为连续地面的前场/广场，建立分片平面或约束三角网。中间缺测可做明确标记的插值/拟合，保存控制点、方法、影响范围、与原 DSM 的高差和不确定性。推算不是实测，也不能只以“尽量平”作为全部约束。
5. **证据不足时保留缺口**：无可靠控制点、跨层关系或高程基准时，不以零米、全区中值或统一桥高补齐；保留待核实区域，不能标为已还原/已可通行。只有屋顶污染证据而无室内地面资料时，可研究在核实封闭实体范围内同步裁除被误用的 DSM 表面，内部地面仍为未知，不因此开通路线。
6. **替换受控区域表面**：通过 `tools/sz/build.py` 生成派生地面和边界，替换该范围内不适用的旧表面，而不是把新平面盖在旧山包上。接缝采用共享边界顶点/高程，校验与邻接地形及已有工程面的连续性；不得靠半透明、厚底座或任意长坡遮住缝隙。
7. **同步建筑与所有使用方**：复核建筑基底、入口、裙房和场地关系，不改已知楼高或移动真实足迹。显示网格、人物/车轮接触、碰撞、树木街具摆放、传送及自动路线验证共用新表面身份和几何，不能只修画面；派生面更新后清理旧接触缓存并重验路线。

建筑占用、草坪裁切和表面重建必须按竖向区间处理：封闭地面建筑下的污染面、架空楼下可通行地面、屋顶花园、地下空间顶板是不同情况。既不能让草坪穿进封闭楼体，也不能将地标整块足迹做成禁行实心盒子。真实台阶、挡墙和坡道有来源才建，不自动生成结构替所有冲突收口。

### 11.4 数据报告与验收

每处增加处理清单：源对象、原始高程来源/日期/基准、控制点及证据、异常判断、派生方法、受影响边界、最大/分位高差、接缝误差、估计状态和未解决项。报告应能复现原始/处理后剖面，不能仅给最终“更平”的截图。

- **画面**：同机位对比地面、斜视和俯视，原本应平顺的路面/前场无屋顶形山包、尖脊、露缝、重复叠面闪烁；入口不埋地，楼底不悬空，草坪不覆盖地面实体。保留并说明真实高差。
- **几何**：连续路段与场地接缝没有非设计台阶，已知边界共享顶点；量测坡度和曲率是否符合该处来源约束。计算误差容差与地理精度分开说明，不以毫米级网格一致宣称毫米级测绘。
- **接触与通行**：实际步行“人行道—前场—入口”，驾车双向跨路段/路口接缝；车轮不离地/陷地，人物不掉入基座、不被隐藏旧地形挡住。架空层、连桥、桥上桥下分别测试，源高程未知处不强连自动驾驶。
- **范围控制**：处理边界外源地形不被意外改变；保留自然山坡、河岸、下沉广场和合法屋顶花园。新增精细网格只用于必要区域，按10号文档检查性能。
- **状态**：只有来源、生成、显示、同面接触和实际操作都完成，才标该样段解决；尚缺真实地面依据的区域继续列出，不以全城平整率冒充真实性。

## 12. 建筑尺度、道路完整性与深圳街道样貌专项

2026-11-09 用户反馈：建筑大小、比例和高度观感不对，南山部分楼异常高或低；道路中间偶有楼体或空缺，希望还原连续路面、中央绿带及路侧小树。本节仅记录待实施计划，不表示已确认每处问题的成因，不恢复暂停的功能开发。当前状态以[交接文档](HANDOFF.md)为准，执行前按[下一轮计划](NEXT-AGENT-PLAN.md)锁定工作树和证据；本节补充第3、4、5、11节，不替代地面P0。

### 12.1 建筑尺寸与高度核验标准

将平面长宽、朝向、相对楼高、绝对基底、塔裙关系和屋顶形态分别检查。DSM抬高基底、裙房误当主楼、父楼与部件重复、相机透视都可能造成比例失真；不能见到高低不齐就统一抬高或压低整片建筑。

| 核验项 | 对照依据与判定 |
| --- | --- |
| 足迹、长宽和朝向 | 使用同一坐标系的可靠测绘、总平面或核实影像；区分墙脚、屋檐、屋顶投影和裙房，记录配准误差，不用透视照片直接量平面尺寸 |
| 建筑高度 | 优先适用的已建成测绘、竣工或可追溯项目资料；统一屋面、结构顶、尖顶等口径，规划限高不等于实建高度 |
| 层数推高 | 层数与每层高度分别有来源；换算结果仍是估计，不将统一层高视为真实楼高 |
| 塔楼、裙房与架空层 | 核对源ID、父子关系、上下界和部件范围；不能给全部部件继承主塔总高，也不能用裙房高度覆盖塔楼 |
| 基底与可见高度 | 楼体相对高度与地面绝对高程分别报告；楼被埋、底部悬空或DSM抬高时，先按第11节核地面，不能改楼高抵消 |
| 天际线和立面比例 | 固定位置、朝向、视场角、时段比较地面、斜俯视与远景；窗层节奏不能暗示与源层数矛盾的楼层数量 |

地标沿用11号文档的高度误差不超过3%要求，但必须先统一高度口径与参照可靠性。普通楼与可信参照的差值超过 `max(3米, 参照高度×10%)` 时进入人工复核；此值仅为本项目拟采用的异常筛查阈值，不是测绘标准、通过容差或自动改高依据。无可靠参照的对象明确记为未知/估计，不能算“高度验证通过”。平面误差按来源精度及配准残差报告，不预设全城具有米级测绘精度。

当前管线审计重点：统一3.2米层高、用途/面积分档加固定种子浮动估高、跨源重叠加权回填、父子部件继承、单位解析及高度截断。逐对象保留原值、来源、换算过程、候选新值和是否采用；不因另一数据集数值不同就自动覆盖。遥感预测和同源转录不作为独立实测证据。

南山首轮审计后海、科技园、留仙洞三个样区，每区选10栋，以源对象集合锁定范围，覆盖当地实际存在的高塔、裙房、普通办公或住宅。抽样优先包含用户观感异常及低可信高度对象；不存在的建筑类别不凑数。30栋是核验工作量，不代表全区准确率。先交逐栋差异表与同机位图，再决定是否扩大或修正生成规则；真实高低差必须保留。

### 12.2 路中楼体与路面空缺的分类修复

每处问题建立稳定编号，记录源建筑/道路ID、位置、朝向、截图、当前显示面和接触面，先定位再改动。

- **路中有楼**：分别排查错误建筑识别、父子重复、源数据年代冲突、坐标偏移、道路过度加宽和真实架空结构。平面相交仅产生审核候选，须结合竖向实体和实际路权判断；不能批量删除相交建筑、缩楼或移楼让路。复用车公庙逐对象核实排除的经验，不扩大其排除结论。
- **路中空缺**：区分真实中央绿带/交通岛/开口、缺铺装、路段接缝、三角网裂缝、地形盖路、桥隧分层及加载缺失。真实分隔空间不得统一填沥青；本应连续的同层行车面不得留下非预期缺口。
- **修复依赖**：源对象错则先纠源，断面错则改断面，网格或接触错则修对应转换。真实高程不足时保留未决，不以全城压平或虚构桥面高度补通。
- **一致性**：铺装边界、车道中心、标线、绿带边缘、人物/车辆支撑及自动路线共用已核断面与表面身份；修复画面后必须检查旧碰撞面是否仍在。

### 12.3 深圳道路断面、中央绿带和行道树

复用深南大道车公庙/红树林路口、北环新洲已有样段，增加深南大道科技园段的资料对照。新增段先按真实源节点和可靠资料锁定范围，不在文档中手写未经核实的坐标。首轮只实施证据最充分的一段，其余保持审计状态，不同时扩大三个街段。

逐段绘制“建筑前场—人行道/骑行空间—路侧绿带—辅路—主辅分隔—主路—中央分隔”的实际断面；这是一份核查项目表，不要求每条路具备所有层次。记录双向是否分幅、各幅车道数、铺装是否连续、中央是标线/硬质隔离/植被，以及真实转向开口、端头和过街口。不得把整条大道总宽重复赋给每条中心线。

中央绿带、主辅分隔带、机非分隔、路侧树池和交通岛分别保留真实边界。依据资料组合地被、灌木、小乔木和成熟乔木；用户提到的小树是应核实的尺度类型，不是将全城树木缩小。树位、树高、冠幅、树种分别注明来源；有树列证据但无逐株点位时可明确标注程序化布置，不能称为实测。保留路口视线、车道、入口和步行净空，不随机填树遮住空缺或穿模。

可继续核验的深圳本地资料（2026-11-09检索，采用前须阅读对应图页并核对年代和具体路段）：

- [《深圳市地名志》](https://pnr.sz.gov.cn/attachment/1/1442/1442495/10537363.pdf)：有深南大道历史断面和中央、两侧绿带记载；只作历史与空间组织线索，不能将历史宽度直接套到当前所有路段。
- [20号线二期南头古城站绿化资料](https://cgj.sz.gov.cn/attachment/1/1565/1565831/12103432.pdf)：包含深南大道相关树木清单，可查树种、尺寸和迁移状态；迁移清单不等于当前原地树位，适用范围也不外推至科技园。
- [2026版非涉密测绘地理信息成果目录公告](https://www.sz.gov.cn/szzt2010/wgkzl/glgk/jgxxgk/gtzy/content/post_12759230.html)：提供三维及测绘成果线索；目录存在不等于已取得可下载、可使用的建筑实高或裸地成果，延续交接中的获取限制。
