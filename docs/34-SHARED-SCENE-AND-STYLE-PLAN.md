# 深圳场景统一规范、基础数据与复用模块计划

更新：2026-11-12。状态：详细规划完成，尚未实施。对应 T13，与 T4/T7/T8/T10/T11/T12 的既有能力衔接。本文件是本轮方案的唯一入口；实施提示词在对话中提供。

## 1. 目标与取舍

本次优化范围限定为**统一规范、统一基础数据格式、物品/装饰/行为模块复用，以及地理区域、山区、道路的参数配置**。目标是同一种能力只维护一份，已有场景多处复用，后续添加内容时主要增加数据和参数，特殊情况通过明确的扩展处理。代码和计算量减少是复用后的收益，不单独追求大规模性能改造或改造玩法。

参考纽约的程序化风格，将深圳整理为共享实现、类型默认值、必要事实参数和特殊行为。功能不受影响、体验差别不大的装饰与外观可使用相同默认值；地区有实际差异时允许配置参数，无需复制模块。

- 保留真实建筑足迹、高度来源、地标辨识轮廓、道路连接和分层关系。统一的是生成方法与表现细节，不是把楼改成同一种形状。
- 写字楼室外公共前场统一石材铺装；本计划不增加室内地板或室内玩法。住宅、低层住宅/小别墅共用已有楼体和近景部件，避免新增独立生成系统。
- 首期环境人群总预算 140 人、环境汽车总预算 30 辆，玩家不计入；专用场地的人物也纳入同一人群预算。密度配置只分配预算，不让每个区域另开一池。
- 观察、无人机和节目操作入口统一放在**左下角 HUD 地点/路牌正上方**，不是悬浮在三维路牌上。
- 先共享基础能力，再验证三类样区，最后迁移其余已有场景。新建隧道、补全真实过街网、扩大城市内容、采集新数据和解决全部历史缺陷仍按原任务推进。

本方案允许同类材质、装饰和布局默认值出现轻微视觉变化，替代旧“纯重构完全不改画面”的限制；功能、来源真实性和通行约束继续保持。下文的人数预算、按钮位置及通行规则作为共用接口的目标约束；若兑现它们需要独立功能修复或体验调整，记录到对应任务，不将其混入这次规范和模块迁移的完成条件。

## 2. 纽约经验与深圳现有基础

纽约依据为已核对的[源码调研](research/slop-newyork-scene-techniques.md)：上游 `2813185` 与本地参考的 45 个 JS 文件内容一致。下表是机制摘要；详细源链接、数量口径及限制见该调研。

| 问题 | 纽约机制 | 深圳采用方式 |
| --- | --- | --- |
| 外墙怎么“贴”、有几种 | 普通楼主要靠程序化着色器生成窗格和墙面：2 个家族、5 个预设；外围另有 5 种图案，地标还有专材质，不能合称全城固定 5 种 | 共用少量着色器和参数，窗格按墙面局部米制坐标排列；避免每栋生成图片、材质和独立纹理 |
| 建筑与地标 | 源轮廓楼、外围模板街区、地标/特殊场所三条生成路径；地标复用盒体、立面和设备 | 保留深圳源对象身份，沿用普通楼与地标生成器，合并相同部件；避免范围剔除误删邻楼 |
| 商圈与地面 | 区域规则影响已有建筑、铺装、招牌、树灯；铺装纹理由共享材质完成 | 一个区域引用多个既有对象，复用铺装和街具，不把整个商圈重做成专模 |
| 车道线与人行道 | 标线条带从车流路网派生，虚线用材质周期；人行道实体与表面板缝分开 | 共享车道断面、路口语义及活动表面，标线随真实坡面和层级走 |
| 人行灯与行人 | 信号有共同计时，路径缓存后局部选路、绕障；不是全员固定往返脚本 | 借鉴共享状态和路径缓存；补齐输入一致性，避免照搬纽约灯具方向、障碍和地高不同源的局限 |

深圳已经有可复用资产，不重新造一套：`sz-materials.js` 的 8 个立面用途预设、`sz-buildings.js` 的源轮廓/屋顶、`sz-building-details.js` 的近景部件、`sz-landmarks/parts.js` 的地标部件、`sz-controller-surfaces.js` 的表面解析、道路车行范围、`sz-trees.js` 的树种/LOD、`PersonRig/PersonCrowd`、`sz-vehicles.js` 的载具，以及 `sz-ui.js::wireShowPrograms` 的节目界面。

这些是当前实现依据，不意味着全部场景已验收。既有功能和缺口以 [HANDOFF](HANDOFF.md) 为准，空间规则以 [32 号](32-ROAD-NETWORK-AND-STREET-PLAN.md) 为准。

## 3. 少量参数，避免配置膨胀

配置分为三种，各有唯一归属：

| 内容 | 保存方式 | 例子 |
| --- | --- | --- |
| 源事实 | 沿用数据管线和稳定对象 ID，保留来源与未知值 | 足迹、高度及其来源、道路方向/层级、场地边界、开放权限 |
| 通用表现 | 在现有责任模块保留一份小型预设表；同类共享默认值 | 立面窗格、石材颜色/板缝、栏杆和路灯样式、近景部件尺寸 |
| 必要差异 | 区域环境、形态或实际行为需要差异时，以已声明的参数稀疏记录 | 住宅阳台有无、已知坡顶、山区路径样式、有效种植带宽度、节目 ID、模拟人流权重 |

优先使用已有建筑类型、道路等级和区域类型；一个类型直接选择一个默认预设。仅有实际消费者时才加入参数；外观与用途推断保留“模拟/估计”语义，不写成事实。未知用途使用中性立面，不自动认定是写字楼或别墅。

不新增逐楼材质配置清单、每个公园一套参数文件、多层外观覆盖链或通用规则语言。实施时将 [区域方案](REGIONS-PLACES.md) 中尚未实现的外观配置设想收敛到上述最小模型，保留已有边界、身份、来源与权限契约；以本方案作为本轮精简范围的取舍依据。

区域通过下列明确的参数组配置，按需要启用；边界继续引用已有 `mapRegions`/场地数据。楼距、建筑朝向和道路宽度从几何派生，不再复制成独立外观参数。

### 3.1 基础格式：共同语义与分类载荷

以下字段和接口是**待实施契约**，不表示当前城市包已具备。沿用 JSON v2、既有 ID 和来源机制，在构建/解码边界做一次适配；相同含义优先保留现有字段名，不能为了统一命名重写全部源数据。统一字段含义和引用关系，不强迫树、建筑、道路、节目使用同一巨型对象。

| 共同部分 | 约定字段或语义 | 必须明确的规则 |
| --- | --- | --- |
| 版本 | 配置文档的 `schemaVersion`；生成结果沿用城市包版本 | 配置版本与包版本分开；不支持的版本在加载阶段报错；有语义变化时由适配器迁移 |
| 身份与类别 | `id`、`kind`、已有 `sourceId/sourceIds` | 源对象保留原 ID；派生实例采用稳定的“源 ID＋部件角色＋序号”，避免随加载顺序变化 |
| 空间 | 既有几何引用；实例变换；`surfaceId` 和层级 | 米、弧度、x 东/z 南/y 上；原点沿用规范。地面绝对高、楼体相对高、表面偏移分开；layer 不是米制高度 |
| 模板与参数 | `presetId`、模块声明的 `params` | 模板定义默认值；实例只写必要差异。公共资源以 ID 引用，不逐实例复制几何和材质 |
| 归属与证据 | 区域/场地引用、既有来源引用、字段可信状态 | 名称不作唯一键；事实、估计、设计、模拟分别标记。继续保留 `heightSource` 等事实专用字段 |
| 行为绑定 | `behaviorId`、行为所需路径/目标引用及参数 | 几何不包含行为脚本；仅有行为的对象填写。路径、目标和对象身份必须可解析 |
| 派生约束 | 活动表面、碰撞体、占用预约、允许模式 | 源事实与权限由负责模块解释，生成一次供消费者读取；三种空间用途不互相冒充 |

建筑继续使用足迹/部件/高度载荷，道路继续使用边/方向/断面载荷，区域使用带孔边界，物品使用锚点与变换，行为使用状态和目标引用。源几何只存一份；运行时网格、缓存、活动状态不回写为源事实。

每个参数需登记类型、单位、默认值、范围、是否可区域覆盖和生效时机。例如 `spacingM` 是大于零的米制间距，`pedestrianWeight` 是非负模拟权重，`speedMps` 是米/秒，`maxSlopeRatio` 是无量纲坡比。枚举写清合法值；参数不使用没有单位的 `distance` 或含义不明的 `level`。

省略值表示沿用默认；`null` 仅在字段声明允许时表示未知，不能等同零；`0` 和 `false` 是显式值，不能被真假值兜底覆盖。未知字段、非法枚举、负密度、失效引用和重复 ID 在构建/加载边界报告具体对象和字段；已加载实例不在每帧重新校验格式。

### 3.2 地理区域、山区和道路参数

| 配置对象 | 可配置内容 | 数据与能力边界 |
| --- | --- | --- |
| 地理区域/街区 | 铺装预设、植被预设、街具预设、模拟人流/车流权重 | 引用区域边界；区域设置只影响声明可继承的表现字段，不改建筑用途、公共权限或源足迹 |
| 山区/坡地 | 路径铺装、灯/树/座椅间距、摆放允许坡比、与路径的退距、沿面朝向 | 高程仍采样所属表面；坡比参数决定某种物品是否适合放置，不削平山体、不生成不存在的通路 |
| 道路/路段 | 断面预设、标线预设、路缘/灯杆样式、路灯间距、绿化带预设、模拟车流权重 | 已知宽度、车道数、单行、桥隧和限行由道路数据负责；缺失值才使用有估计标记的默认 |
| 公园/滨水 | 步道预设、植被混合、岸边设施预设、设施退距、模拟人流权重 | 水位、岸线、步道权限和真实入口独立保留；公园内独立公共道路遵从自己的道路记录 |
| 建筑/场地 | 立面、首层、阳台、屋顶、前场和装饰预设 | 只覆盖模块允许的字段；地标识别结构和实际入口保留专用数据 |

这些参数是复用同一生成器的输入，不是为每个地区创建一个新类。山区可与公园、地理区域重叠；道路也可穿越多个区域，不能以“属于山区”覆盖道路身份。对象归属用于查参数，空间加载分块只负责加载，两者不互相替代。

解析规则固定为：**类型预设 → 对应参数组的区域/环境覆盖 → 对象或路段显式参数 → 事实与通行约束校验**。类型预设只选一个，不做递归继承；区域层按参数组选择一个归属者，不把所有重叠面反复叠加。已核场地归属优先；无明确归属且多个同类候选冲突时保留类型默认并记录冲突，不能依赖数组顺序或任意选择最小多边形。

例如山区参数负责设施坡比限制，商圈参数负责人流权重，路段参数负责灯杆间距；它们可组合，但只覆盖各自获准字段。道路跨区时仅在必要边界划分表现子段，保留源道路 ID 和拓扑；行车连接及连续标线里程不因风貌切段而断开。人车权重不累计相加；跨区变化平缓应用，避免重复实例和突然重生。

以下仅为配置形状示例，ID、数值均为演示，非深圳实测值；字段尚未实施。真实对象从区域引用或稳定源 ID 绑定，通行权和道路事实不放进此表现配置。

```json
{
  "schemaVersion": 1,
  "bindings": [
    {
      "target": { "kind": "region", "id": "example:mountain-park" },
      "params": {
        "surfaceStyle": "gravel",
        "vegetationStyle": "mountain",
        "pedestrianWeight": 0.6,
        "placement": { "maxSlopeRatio": 0.25, "pathSetbackM": 1.0 }
      }
    },
    {
      "target": { "kind": "road", "id": "example:road-segment" },
      "params": {
        "lampStyle": "standard",
        "lampSpacingM": 30,
        "medianStyle": "grass",
        "trafficWeight": 1.2
      }
    }
  ]
}
```

上述山区坡比只限制配置允许覆盖的装饰摆放；不代表车辆限坡、玩家可攀爬坡度或工程规范。没有实际中央绿化带时，`medianStyle` 不会创造一条绿化带。没有有效路径时，人流权重不会凭空产生行人。

### 3.3 物品与装饰模块契约

物品包括树、灯、座椅、栏杆、标牌、车辆及建筑附属物；装饰包括铺装表现、招牌、花坛和灯效等。二者按实际能力组合，装饰名称不决定是否参与碰撞。沿用现有 `plan*`/`build*` 分工：

| 阶段 | 输入 | 输出及责任 |
| --- | --- | --- |
| 参数解析 | 源对象、类型预设、区域绑定 | 已校验、带解析来源的有效参数；公共消费者只读此结果 |
| 布局 `plan*` | 有效参数、所属表面、同源占用查询、固定种子 | 实例变换/路径、资源引用、明确的空间用途；不创建 GPU 资源、不改共享源数据 |
| 构造 `build*` | 布局结果、共享几何/材质资源 | 网格或实例批次及所属表面/碰撞/预约登记；同种资源跨区域复用 |
| 更新与释放 | 仅动态对象的状态、时间步；所属分块退出 | 更新必要状态、撤销登记、释放自有实例；共享资源由资源拥有者释放 |

无需让每个静态物品具备空的 `update()`，也不新建通用 ECS、动态插件引擎或物品继承树。现有模块不符合接口时采用最小局部适配，迁完消费者后删除旧入口。

### 3.4 行为模块契约

行为按能力复用：沿路径移动、等待信号、跑步、停留观看、相机观察、跟随目标、节目播放。普通人和特殊人物可以使用同一移动能力，专用节目仅组合它需要的能力；不把所有状态机合成一个巨大控制器。

- 输入统一为对象/目标 ID、路径与活动表面引用、有效行为参数、时钟和必要服务。路径权限、信号状态、接触高度都查询各自唯一拥有者；行为模块不再私自生成一套路网或灯相位。
- 有进入/退出的行为明确 `enter`、`update`、`exit` 语义；静态能力不强制实现。失败返回原因，切换前先验证，退出可重复清理且不会恢复过期会话状态。对象位置和相机分别只有一个当前写入者。
- 速度、停留时间、观看距离等成为有单位的参数；人物移动、节目时间和输入控制使用明确的时间来源，暂停节目不暂停城市交通。具体函数名适配已有接口，不为统一名字制造转发文件。
- 先保留现有行为轨迹和状态转换，提取公共资源、查询和生命周期。新增行为时登记能力 ID、所需参数和结束/失败条件，不在公共循环添加地区名称判断。

### 3.5 特殊情况与后续添加

新增一个区域：绑定已有边界，选择预设，填必要差异；新增同类物品：引用已有生成器并增加实例数据；新增外观变体：增加预设；只有现有能力无法表达的新几何或新行为才增加专用实现。正常新增不需要修改 `main.js` 的地区分支或复制另一区域的文件。

专用实现仍消费共同数据、资源和空间服务，并遵守同一更新/释放契约。仅通过代码中的明确注册表绑定稳定类型或对象 ID；JSON 不携带函数、动态导入路径或任意可执行表达式。扩展记录说明适用对象、差异原因、输入字段、输出能力及验证场景。相似例外出现第二个消费者时，重新判断是否可转成共享能力或参数。

### 3.6 存储、适配与渐进迁移

源事实继续放现有 `data/source/` 体系；只被一个模块使用的表现默认值放该模块，多模块消费的预设由一个明确拥有者导出。需要可维护的跨区域绑定时才增加一份小型配置，不按每个地方新建文件。公共契约记录在现有组件文档，不建立平行文档体系。

构建/解码阶段将旧结构适配为共同语义，消费者迁移后只读规范化结果。先兼容现有正式包；确需新增载荷字段时经 `tools/sz/build.py` 和数据校验生成，保持两个包语义相同。逐批迁移并删除本批消费者的旧字段读取和重复默认值；旧输入格式仍受支持时保留边界适配，输入退役后再移除。兼容读取不等于维护新旧两套可编辑配置源。

## 4. 共享模块与迁移内容

以下是职责划分，不要求逐行创建新文件。优先收敛到现有拥有者；至少两个真实消费者需要相同能力时才抽取共享实现，接入后同步删除旧副本。`main.js` 负责装配，不继续累积地名判断。

各条描述公共模块应承载的语义和迁移方向。实施时逐项区分“已有能力改为共用”和“尚缺能力需要新增”；本次只承接前者及其必要适配，后者归对应功能任务。此前执行提示词中超出这一范围的功能调整，以本文件当前范围为准。

### 建筑、材质与近景部件

- 合并 `sz-materials.js` 与 `sz-building-details.js` 的重复立面分类和默认值；材质、阳台/首层选择使用同一预设含义。若生成器也消费分类，保持其映射受校验，避免新增一份手工镜像。
- 写字楼共用幕墙/窗格与室外石材；住宅共用窗格、阳台、空调、屋顶设备；低层住宅/别墅仅在已有来源支持时选坡顶等变体。商铺复用首层开间、雨棚和招牌部件，避免逐店生成新材质。
- 保留已核建筑形体，尺寸、数量、颜色和固定种子驱动部件。细微色差、板缝、栏杆造型等直接用家族默认值；特殊对象 ID 仅为可核实形态或功能服务。
- 普通楼、地标和近景共享屋顶设备布局与避让结果；已有共用 `roofPlan` 继续沿用。近景突出物按距离生成，远景保留同一楼体和材质身份，避免重复屋顶和跳变。
- 地标继续采用专属识别轮廓；复用 `sz-landmarks/parts.js`、材质和实例批次。架空层、门廊、桥下的实体分段与接触面保持，不能为合批封成整块碰撞盒。

### 道路、铺装、桥隧与场地

- 以现有道路系统生成唯一车道断面结果：方向、有效宽度、车道偏移、分隔带、停止位置与层级。`sz-road-markings.js::createLanePlan` 和 `sz-traffic.js::laneOffsets` 收敛到同一结果，供标线、环境车与自动驾驶读取。缺少车道数时只估算一次，保留估计标记。
- 延续条带几何与程序化标线；顶点从所属路面/桥面取高，采用统一小偏移防闪烁。线条、灯杆、停止点和通行规则共用路口身份及方向；同一信号状态驱动灯面、车与人，移除已确认无消费者的旧计时函数。
- 红绿灯按受控路口的有效进口和过街方向派生，不按区域固定塞若干盏。当前道路前场数据有 1 个受控路口、4 个进口；代码每进口最多 1 杆、每杆 2 灯头，这是生成上限而非全城实际灯数。后续统计“路口、成功放置杆、灯头、受控方向”四项，防止混用口径。
- 公共铺装先统一石材、水泥、石子、木栈道四种常用表现；沥青、草地和水面保留各自语义。共用米制纹理、边缘、厚度、批处理和接触登记。只有改变几何/通行的差异才保留独立路径。
- 商圈边界用于风貌和人流分配；铺装只覆盖已有可用公共前场/步行面，裁去同层车道、建筑、水体及禁入部分。高架投影不切断地面广场；整个区域面不能直接变成石地板。
- 沿道路依次确定车行边界、必要净步行带、可用树灯带、建筑前场。保留真实楼距；空间不足就减少装饰。中央分隔带只在有效区域存在时选择草地或树木；树冠、树干和底座均不得侵入车道及必要净空。未核实的绿化作为模拟配置。
- 桥梁、匝道复用桥面、栏杆、桥墩和连接几何；特殊跨越仅保留跨度、曲线、标高及识别结构。源数据中的桥/隧道路边数不是独立设施数，禁止据此批量造模型。当前隧道是离线审核能力，不能把 `tools/qa/sz-tunnels.js` 当成已接入的运行模型；新隧道仍由道路任务另行实施。
- 地势过渡只处理有来源或已明确为派生工程面的接缝和坡道；保留自然山体与真实台阶。显示、脚/轮接触、通行和净空用同一分层表面；不以整体压平、公园隐藏斜坡或横跨车道的铺装掩盖冲突。

### 公园、树灯与滨水设施

- `sz-streetscape.js` 的同类简易树与 `sz-trees.js` 收敛到现有树种/LOD资源；树种、尺度和种植方式用少量预设。已核树位保留，模拟树按固定种子生成。地图公园边界、真实植被和模拟种树分别标记。
- 高尔夫场地、人才公园、深圳湾、莲花山和交流中心场地中相同的铺装、栏杆、边缘、树灯和表面登记复用；岸线、水位、路径和地势仍由各场地数据定义。公共设施不再每个场地复制网格工厂。
- 先预约连续步行带和车道，再放树、灯、座椅。复用已有车行避让范围与空间查询；保留“摆放预约”与“实体碰撞”的不同含义。合并 `pathAt`/高度查询接线时保留所属表面、桥隧层级和允许模式，不把所有路径降为地面。
- 公园步道默认仅供步行；环境车生成、汽车规划和玩家汽车落点读取同一权限。公园中的独立公共车道按源道路处理，不能因为位于公园范围就被误删。入口、开放状态和跨层连通未知时沿用已有可靠路径，不凭外观推定可达。

### 人群、汽车与密度

- 使用现有人物、车辆模型和池；人物走路、跑步、观看复用同一资源与预算。人才公园专用人物纳入 140 人上限，保留观看后回到路线的行为；不为每个公园另开完整人群系统。
- 以有效可行走长度/面积、区域模拟权重和附近可见范围分配人数；以有效车道长度、道路等级和模拟车流权重分配汽车。采用统一预算分配与余量再分配，零权重或无有效路线必须为零，修正最低人数兜底覆盖零密度的情况。
- 商圈只改变有效公共路径上的分配权重，不在整个多边形内撒人。车辆从合法车道上的安全间距位置出现，离开活跃范围回收；使用进出范围滞回，避免镜头前闪现、跨区清空或反复重生。
- “稀疏、普通、繁忙”等为模拟档位；以后可接入带时间与来源的车流/客流数据，仍经同一预算分配。界面不得把当前屏幕 30 辆车或 140 人解释成真实城市流量。
- 路网、静态通行检查和候选路径按版本/分块缓存。普通 NPC 沿有效路径局部选目的地，玩家保持自由控制；复用障碍、表面和权限，不强制所有角色共享一套寻路算法。完整过街和广场绕障缺口继续由 T8 负责。

### 操作入口、对话框与特殊节目

- 复用现有 DOM、文案表和节目界面。统一按钮容器、弹层外壳、关闭/返回、焦点及输入恢复；观察、无人机、节目按稳定顺序显示，每种选择最近且符合条件的目标，离开范围自动更新，窄屏可换行。
- 观察/无人机按钮排在 HUD 地点路牌上方；节目入口遵循同一布局。普通对话框与节目面板共享外壳，内容控件仅保留各自需要的部分。
- `wireShowPrograms` 已共享节目菜单与部分会话恢复逻辑，直接整理复用。跨观察/跟拍/节目统一“验证目标→进入→更新→退出/恢复”生命周期；切换失败保留原会话，同一时刻一个活动观察会话。
- 相机、输入和时间的恢复责任集中在会话所有者，保留最初进入前的状态；节目播放能力与普通观察能力分别按需接入，不让普通弹框承担节目时间轴计算。

## 6. 复用带来的计算与加载精简

以下只处理模块归一过程中实际重复的资源和计算。独立的加载架构改造、降频策略、全城性能治理及压缩实验不纳入本次完成条件。

1. **一次生成，多方读取。** 同一道路断面、同一屋顶布局、同一场地裁切及同一语义的空间索引只有一个拥有者。显示/接触/避让可消费同源结果，仍保留各自语义；不能为了省索引混淆实体碰撞与摆放范围。
2. **静态结果移出逐帧循环。** 在数据构建或分块加载时完成稳定几何派生；运行时只更新活跃人物、车辆、相机和节目。动态碰撞/信号正确性优先，降频须验证完整运动周期。
3. **按实际重复共享资源。** 同类材质缓存、部件实例化、空间分块合批；装载区域时读取小参数，复用共享资源。分块卸载释放自身实例，共享资源由唯一所有者管理，避免卸载一处破坏另一处。
4. **统一资源生命周期。** 保留近景和节目现有加载时机，共享资源获取、失败清理和释放；退出释放场景对象，共享代码/材质可保留缓存。若需要另改懒加载策略或预加载链，记录到性能专项；已有按需创建的内容不计作新收益。
5. **缓存有失效边界。** 以源版本、参数版本和空间分块标识缓存；参数改变更新受影响块，其他块保持稳定。无需运行时全图重复扫描、重新解码地表或重建所有路径。

本轮衡量删除的重复实现、减少的材质/几何创建、索引次数、活跃更新和实际加载字节。现有计时、单套地表解码、离线隧道审核不重复记功；数据压缩与编码实验继续归 [31 号](31-PERFORMANCE-AND-LOADING-PLAN.md)，不作为此次通用化的强制前置。

## 8. 验证与验收边界

- 格式验收覆盖缺省、显式零/false、允许的未知值、非法参数、版本迁移和失效引用；配置验收覆盖重叠区域、山区与公园叠加、跨区道路及对象显式覆盖。比较规范化前后的源 ID、几何、高度来源与权限，确保表现参数没有篡改事实。
- 复用验收使用同一物品/行为模块服务两个已有地点；只改参数即可形成变体，共享资源仅创建一份或按必要批次创建，卸载其中一处不影响另一处。特殊行为仍能独立进入、结束和恢复。无需为验收新增真实世界内容。
- 按 [25 号](25-FAST-CHECKS.md) 运行相关检查；共享核心整合后执行全量。对本次迁移的已有能力，重点检查车道偏移、信号与权限、零密度、预算合计、跨区去重、上下层接触、卸载与会话失败恢复；已有缺陷单列，不能为迁移默默改变其行为。测试观察行为与契约，不为简单常量或外观合并复制实现。
- 在内置浏览器同机位核对受影响的日夜、近远景、窄屏按钮及实际步行/驾驶输入。迁移不得新增公园汽车、树灯挡路或铺装遮挡，真实坡度与地标轮廓保持；已有同类缺口仍在对应任务验收。
- 如报告性能收益，对照须固定设备、视口、路线、人车数量和近景质量，并说明实测指标。此次必须检查资源重复创建和明显回退；完整启动/帧率/内存专项仍按31号执行。未测项明确写未测，不承诺未经测量的百分比。
- 迁移范围的代码变化、删除的重复逻辑和地区分支单列；格式校验、必要适配及测试增量另列。以规范一致、实际复用和后续易添加为主要结果，不为压低总行数省略必要的数据校验或迁移支持。
- 启动既有错误或缺失源数据阻断样段时，保留原始证据并标记依赖；可继续独立的共享整理，但受阻范围不能宣称验收完成。局部通过不升级为全城 L5，正式性能门槛仍见 [10 号](10-PERF-QA.md)。

本轮交付仅为本计划及状态引用，未修改运行代码、正式数据包或验收结论。后续实施以“基础格式一致、公共能力多处复用、区域参数可配置、新增内容少改代码、特殊情况独立扩展、现有功能保持”为完成标准。
