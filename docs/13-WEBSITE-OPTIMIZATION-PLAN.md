# 13 网站加载、数据与运行性能优化计划

日期：2026-11-09。状态：规划，尚未实施或验收。对应 TASKS 末尾的网站优化任务，归入 M9，不替代既有里程碑。

## 1. 顺序与约束

先完成[12号规划](12-URBAN-FABRIC-PLAN.md)第11节的道路、建筑接地和穿模 P0；性能测量、启动错误提示可同步推进。待共用表面契约稳定后，再迁移数据格式和分块加载，最后扩大近景细节及模拟人数。

不以压平真实地形、删除来源字段、合并桥上桥下或减少必要碰撞来换取性能。原始资料及哈希保留；生成产物只经 `tools/sz/build.py`。保持原点、源 ID、固定种子、地标轮廓、内院及架空通道。未知地面保持未知。继续使用原生 ES Module、顶部静态 import 和锁定版本的 import map，默认不增加打包工具或 npm 运行时依赖。2026-11-09 用户补充要求代码可读性及打包后体积/速度优化：本计划允许评估独立发布阶段的构建工具，作为发布优化的局部例外；不改变源码直接运行方式，不引入浏览器运行时依赖。本次仅更新规划，未安装或选定构建工具。按需加载指数据请求和几何创建，不默认改用动态代码 import。

### R：源码可读性与维护

本节为2026-11-09用户追加要求。源码是维护和审核入口，发布压缩文件是可重建产物，不能为了缩小下载包手工压缩源码或把关键逻辑写成难读的一行。

- 按数据解码、空间/表面查询、几何生成、渲染、模拟、UI划分模块，明确输入输出、单位、坐标、高程基准、未知值和资源所有权。避免显示、碰撞、传送各复制一套算法。
- 用可辨含义的函数和变量名；配置常量说明单位与来源。提取过长函数，单文件尽量不超过约1000行，但不为凑行数创建碎片化模块或无必要抽象。
- 保持两空格缩进、顶部静态import、单引号、分号；新增注释用中文，重点解释约束、来源、边界和取舍，标识符、日志和测试名用英文。UI字符串仍集中管理。
- 在模块边界记录数据结构及公共接口，可用JSDoc说明类型；公开有限状态穷举处理，未知状态明确报错。标注创建、更新、卸载与dispose责任。
- 死代码与重复实现先查实际引用、动态注册、测试和兼容入口再删。原版参考保留在只读ref中，不做无关全库重排版。
- 纯可读性重构和性能/行为修改分别提交；以真实场景、接触、路线和确定性回归验证行为不变，避免只测代码形式。

验收时提供模块职责/依赖简图、关键数据契约和调试入口。审核者应能从一次地图传送或表面查询追到来源与碰撞实现；压缩发布中的报错应能通过匹配版本的source map定位源码。

### A：先知道慢在哪里

测量区分页面导航起点、数据就绪、首帧和真正可操作。请求统计分别列本地、引擎、字体和其他外部资源；区分传输字节与解压字节，说明跨域资源计时可见性限制。帧时记录中位数、P95、P99及长任务，不能只截图瞬时60 FPS。

本地服务器队列修复已有[记录](qa/m2-ground/local-server-cold-start.md)，不要重复当作未实现功能。后续重点是加载失败恢复：静态依赖、顶层数据加载及渲染初始化失败都有中文提示与重试，成功后解除启动监听。界面文字集中管理；引擎加载失败前的必要HTML兜底需与字符串表校验一致。缓慢但未失败时显示等待，不虚报失败或虚构进度。

### B：先压缩表示，不损伤城市

第一候选是占包最大比例的地形。比较“完整网格TypedArray二进制”和“规则格网加边界局部不规则网格”两种方案。后者需要明确裁切单元及共享边界，不可因省略索引而填回海岸洞、封闭馆体裁除区或未知表面。第一轮以保持当前运行几何为准，不额外降低高程精度；任何后续量化都需单独说明误差与验收。

审计 `roads`/`roadGraph`、`terrain`/`terrainSurface` 的正式页、MVP、地图、建模和碰撞消费者。用途不同的表示不能直接删；确属重复者改共享索引，源审计属性可留在可追溯清单，运行包保留必要身份及来源映射。

格式包含版本、计数、长度、字节序及校验；坏包不静默回退零米。若解析/几何准备被实测确认占主线程，再试 Worker 与 transferable buffers，记录复制成本和临时内存。维持旧格式比较/回退路径，稳定后再移除，避免长期保留两份全量解码数据。

### C：分块必须连通且可回收

首屏保留城市概览、搜索索引及必要路由拓扑，附近加载详细地面、建筑和街具。地图搜索不应要求先下载全城详细网格。道路跨块共享节点和表面版本；路线前方的数据与碰撞准备好才允许驶入，未就绪处等待，不能猜测地面。传送先加载目标、核验落点，再移动玩家。

按速度、视野与移动方式预取；飞行需要更远的低精度可见范围。下载去重，取消失效任务；卸载须释放几何、实例缓冲及独占材质/纹理，共享资源按引用管理。细节卸载不能让近处碰撞突然消失；眼前交通和路口预约不能随块回收丢失。

### D：减少每帧工作

先核验已继承的 `scene-culling.js`，不要重复增加一套剔除。避免整个城区共享一个巨大包围盒而无法剔除。近景实体细节用于影响轮廓与通行的阳台、雨棚、入口；窗格、窗灯等优先用稳定着色器，远处抗闪烁。LOD降低外观细节不改变同一可通行表面或源身份。

分别量测阴影、半分辨率SSR、Bloom和夜间灯光成本，再定质量档位；档位不得改变交通规则或碰撞。模拟密度遵循12号文档，先降低远处更新频率，不在玩家眼前清空车辆和人群。是否按屏幕空间误差调整LOD须有街道与空中对照。

### E：部署清单与缓存

数据与代码用内容版本绑定；HTML可更新、带哈希资源长期缓存，完整清单就绪后切换版本。文本按服务能力压缩，已gzip的数据避免重复压缩并验证浏览器读取逻辑。评估Three.js及字体随站点托管，保留版本、许可及import map；字体可使用系统回退降低关键路径依赖。

部署只包含经依赖审计确认的运行资源，不携带 `ref/`、原始数据、虚拟环境和QA大图。纽约遗留资源先验证依赖再排除，不在工作树批量删除参考代码。清理部署体积和降低实际首访流量是两项不同指标。

### E补充：打包后的大小与速度

保留直接运行的开发源码，另输出独立发布目录，禁止覆盖源码或手改生成文件。城市数据继续由 `tools/sz/build.py` 生成；发布流程只收集其产物、转换代码并生成版本清单。是否采用打包器/压缩器由实测决定，选用时锁定版本并记录可复现命令，保留许可声明。

1. 对比原生模块发布、仅压缩、按稳定模块组打包三种方案。记录原始JS大小、gzip/Brotli传输大小、请求数、解析/执行时间、冷启动和热更新命中率；不能只按压缩文件最小选型。
2. 发布时可压缩JS/CSS/HTML，按真实依赖移除不可达代码。Tree shaking须审计初始化副作用、场景注册和TSL材质，不能将它们误删。不默认混淆公共属性或序列化字段。
3. 避免把全部引擎、城市代码、数据和低频功能塞进一个巨包；评估引擎与稳定代码独立缓存、数据继续空间分块。代码拆包必须兼容现有顶部静态import/import map约束，不自动引入动态import。
4. 对文本按服务器能力使用gzip或Brotli，检查Content-Type、Content-Encoding、Vary及缓存协商。原有gzip城市文件与HTTP传输压缩分开处理，验证不会重复解压或错误解析。
5. 发布包保留匹配版本的source map作为调试归档；是否公开提供单独配置，不把source map计入首屏必要下载。检查其中不包含本机绝对路径、密钥、原始大数据或无关文件。
6. 从发布目录启动并完成与源码版本相同的冷启动、菜单、地图、驾驶、飞行和接触验证，涵盖相对路径、Worker路径、压缩包与缓存更新。保存体积和时序前后对照，速度改善以重复测量为准，不保证压缩必然提高FPS。

发布优化和R可读性批次分别验收：源码应更易维护，产物应有可测量的体积/启动收益；若收益落在测量噪声内或明显损害缓存和调试，不增加构建复杂度。

## 5. 最终验收与回退

沿用[10号文档](10-PERF-QA.md)：M1 Pro级设备、1440p，冷启动15秒内可操作，地面60 FPS、飞行50 FPS以上，每帧1500次绘制和600万三角形以内，压缩运行数据25 MB以内，显存1.5 GB以内。显存不可直接测量时单列资源估算及工具限制，不能以JS堆替代显存通过验收。新增优化不承诺未经实测的压缩比或速度倍数。

每批用相同数据哈希、路线、种子、时段、视口及缓存条件做前后对照；网络测试记录明确带宽/延迟配置，不能把本地结果当公网结果。覆盖地面与空中、夜景、地图搜索和传送、桥上桥下、跨块路线、断网/坏包和版本更新；现有未实现玩法仍列缺口，不因性能通过而勾完功能。

记录保存到 `docs/qa/m9-optimization/`（实施时创建）：体积清单、原始计时、资源曲线、截图、实际输入路线、精度/接缝及接触回归结果。连续漫游至少20分钟，重复同一路线至少3轮，比较相同停留点的活跃对象和资源数量。发现持续增长需定位并修复，不用页面重载掩盖。

数据格式、分块、GPU调优分别提交和验证。出现来源丢失、几何变化、穿模、掉落、版本混用或性能回退时撤回对应批次，保留可复现证据。完成后更新 TASKS/HANDOFF，恢复普通游玩状态；仅写完本计划不代表优化已完成。
