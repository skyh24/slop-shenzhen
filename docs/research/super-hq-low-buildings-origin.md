## 如何变成这些楼

补充足迹进入城市包 → 缺高估算写入高度 → 根据用途/高度/面积选择 `residential_low` 外观 → 正式生成器挤出墙体、绘制窗格并添加屋顶细节。

当前构建报告 `heightEstimate.groups` 可追溯到具体估算：

- 短楼取250米网格组 `nearby:unknown:1:grid:-38:10`，搜索半径1500米，4个样本均为60米，取中位数的一半即30米作为基准。
- 长楼和GloBFP体量取 `nearby:unknown:2:grid:-38:9`，搜索半径1000米，9个样本的中位数60米，同样基准30米。
- 按对象ID固定的0.8–1.2扰动，得到30.6、34.1、24.7米。结果可复现，但不是这些建筑的实测高度或已知层数。

因此“像住宅”主要是默认外观，“这么高”来自邻域估高；数据没有证明这里确实存在三栋这个高度的住宅。是否为施工设施、历史拆迁轮廓、重复检测或真实保留建筑，仍需要逐对象现状资料，不能凭截图直接删除或定性。

超级总部模型按建成效果生成C塔等设计体量，而普通补充数据仍用于周边楼体，存在设计场景与未核现状轮廓混用的风险。`layout.js::siteTakeoverIds` 只接管指定场地多边形内的楼体中心点，另有固定 `optionalSkipIds`。本次三条对象位于接管范围之外且不在固定名单，所以仍由普通建筑生成器绘制；不能通过任意扩大接管边界清空邻楼。

## 小地图为什么看不到

`sz-map-layers.js::footprintLayers` 遍历同一份 `REAL_BUILDINGS`，本次三条对象都有源足迹。它不是只画OSM，也没有单独过滤矮楼。

`sz-map.js::drawWorld` 只在地图比例 `v.s >= 0.18` 时绘制建筑轮廓。小地图比例随实体世界高度变化：

```text
scale = max(0.05, 0.32 / (1 + max(0, y - 25) / 180))
y = 200 → scale ≈ 0.1623 < 0.18
```

稳定状态下世界高度高于约165米即进入隐藏建筑的范围。截图显示飞行高度200米，所以整层建筑会被隐藏，高楼也不例外。缩放有平滑与背景缓存，跨阈值的显示切换可能略滞后。全图放大到阈值以上也会绘制源足迹，不能由缩小地图上的空白推断城市包里没有这些楼。

另一项独立边界：二维地图读源足迹，不直接使用传入的 `allBlocks`，程序新增裙房和无来源足迹的设计塔楼可能不会完整反映为二维模型轮廓。这不是本次三条普通源建筑缺显的必要原因。
