# 武汉地面与三角路段：深圳复用方案

调研对象为 Slop 武汉只读参考副本 `7a62402a81f3cb50b38e664323f2cf7e4e132eac`。核对构建代码、渲染代码和实际 `WUH1` 地图包；不是对现实武汉逐块铺地的调查，也没有做浏览器外观或连续通行验收。

## 武汉实际做法

| 场景 | 在参考版里是什么 | 证据 |
| --- | --- | --- |
| 草地、树下、普通空地 | 源公园、花园和绿地合入 `park`，林地单独用 `forest`；地图包的独立 `grass` 数组为空。草色由世界坐标下的大、中、小尺度连续噪声叠加，另有很轻的割草条纹和近处法线细节，并非草地棋盘。普通干地则用灰混凝土底、局部沥青色、细缝及少量苔痕作为兜底；没有把无标签空地一律当草坪。 | `tools/import-citywide.py:80`、`tools/build-wuhan.py:70`、`tools/build-runtime.py:149`、`js/runtime/ground.js:225`、`js/runtime/tsl-materials.js:2598` 和 `:3313` |
| 路口或匝道间的三角空隙 | 没有独立的三角岛或导流标线数据层。武汉先把同层路中心线按实际生成的半路宽扩成车道，再多扩 2 米得到路肩候选；从中扣除沥青、步行街、水面和接地建筑。两边的路肩碰到一起时，窄三角就会整个变成带路缘的硬铺；不够覆盖的内部回落到底地材质。若有源绿地，则由绿地层上色，不是“三角一律种草”。 | `tools/spatial_rules.py:26` 和 `:52`、`tools/build-runtime.py:102`、`js/runtime/ground.js:253`；见下方包内抽样 |
| 楼与道路之间 | **有铺地观感，不是所有楼前统一铺石板。** 靠道路的一带是高出地形基准 0.15 米的人行道，程序化灰砖、红色错缝砖或灰米色铺砖，并有竖向路缘；更里面未分类的院落、退界和空地通常是混凝土与补丁沥青的底材。江汉路青石板是专门样段：按源步行街中心线裁入已有步行面，将粗面中带和两边错缝板分开，未跨车道、建筑或水面扩面。 | `js/runtime/city-config.js:14` 和 `:278`、`js/runtime/tsl-materials.js:3271` 和 `:3313`、`tools/heritage_paving.py:5`、`docs/HERITAGE_STREET_DETAIL.md:5` |

武汉的绿地/停车/广场材质代码不等于实际数据覆盖：这份地图包 `park` 有 3,126 个面片、`forest` 有 2,146 个，`grass`、`plaza`、`parking` 均为空，`heritagePaving` 有 7 个面片。面片数包含切分结果，不是场所数。坡地面按地形三角网裁切，桥隧独立；不把武汉的山体范围照搬成深圳的起伏规则。

江汉路实体铺材另有[武汉市商务局转载的改造报道](https://sw.wuhan.gov.cn/xwdt/gzdt/202009/t20200929_1458374.shtml)：中间采用斧凿纹青石，两侧采用较平整的火烧水洗面青石。报道只用于该街材质依据，不用于推断其他楼前或道路岛。

**三角抽样。** 解包后从 `carriageway` 的内环筛选面积 15–400 平方米、简化 1.3 米后为三角且简化后面积不少于原面积 80% 的干地空隙。得到 46 个几何候选，全部与 `sidewalks` 相交，覆盖约 39.7%–100%；这个样本没有 `park` 或 `forest` 覆盖。比如武汉局部坐标约 `(2346, 731)` 的 21.4 平方米空隙全为路肩铺装；`(2244, 632)` 的 281.8 平方米空隙只有约 49.3% 为路肩，其余是底地。只统计闭合小三角，不包含开放尖角、标线区或所有立交，不证明这些都是现实中的导流岛。

## 深圳可复用的规则

**同一块地先确定是什么，再决定怎么画。** 不照抄武汉向两边一律扩 2 米的路肩：这是武汉三角空隙会变成人行铺装的原因，恰好会把深圳双幅路内侧弄成人行道。也不套用武汉的颜色、割草条纹或全城铺石。

| 地面类型 | 判定与默认表现 |
| --- | --- |
| 已知用途 | 水、湿地、公园、停车、现有步道、桥隧实体和洞口、接地墙柱等先用原有表面，不被补地覆盖。只有标记公园边界内允许自然起伏；普通地坪保持平整；上跨、下穿和接坡仍由原工程断面负责。 |
| 楼前石铺 | 优先用已有硬铺、前场或临街地块证据。需补缺时，只在有边界的临街前场内找「近楼、接同层外侧人行道」的空地，扣除实墙、私有或已知用途、绿地、出入口、车道、水和结构开口。程序化灰色小块错缝石铺，接缝近看可见、远看淡出；院落与大空地不整块铺石。无入口或开放证据的补面只改外观。 |
| 路内分隔与三角岛 | 形状不是判据：先区分**沥青内的导流标线区**、**同层车道围出的实体岛候选**和**普通街块角地**。第一类仍是沥青，有标线依据才画，不设台阶；第二类从同层源拓扑和正式车行边界取剩余面，避开过街及落脚点，证据足够才做带路缘的实体岛。小窄处用低调硬质填充或沿用有来源的绿地，较宽有余量的岛可铺草；不生成内侧纵向人行道，不自动开放过街，不为三角岛新增花圃。第三类按地块用途判定，不因形状而被划成交通岛。 |
| 未分类空地 | 仍是中性的平整底地，不冒充绿地、石铺或可步行广场。只借鉴武汉连续的色差和细粒；草坪只在有绿地证据、已配置景观或经复核的宽余地使用，不要格纹。深南大道既有 S 形花圃和短窄段纯草规则不改。 |

## 实施顺序与验收

1. **先做分类报告，不改高度或交通。** 从 `tools/sz/road_frontage.py` 现有基于源节点的岛候选规则开始，与 `tools/sz/arterial_corridors.py` 的双幅分隔带排除范围合用。闭合岛先试，只有平面交叠、开放尖角、桥下投影、无路缘证据的候选先标为待核。用 `tools/sz/urban_paving.py` 已有的干地、地块、车行、建筑、步道和用途遮罩复用选面；报告记录候选类型、证据、面积、冲突与保留底材原因。通用规则不写死街名；仅试点配置使用已核地块和道路 ID。
2. **先改善材质，再做实体台阶。** 未分类空地用 `js/sz-ground.js` 的现有分块材质加轻微色差，不盖新平面；楼前沿用当前小块错缝石铺和 `urban_paving` 的同一地形三角面分区。已核实为实体的岛才复用 `js/sz-road-frontage.js` 的顶面、竖向路缘和接触查询；以现有约 15 厘米路缘为设计参数，不报作实测。标线、草色、台阶与通行权分开，实体顶面和接触查询同源，石缝只影响材质。
3. **三个正例和一个反例再决定扩区。** 建业街—香林路看「外侧人行道 → 楼前石铺 → 草或底地」有无硬缝及突起；深南大道报业大厦段看内侧无纵向人行道、短窄处无花圃、外侧和过街仍连续；从分类报告选一个有证据的三角实体岛，并对照一个只有标线的分流区。另用香蜜湖或车公庙一个分层点反验桥下、洞口和接坡没有被补面覆盖。以同机位飞行俯看和行人近景复核材质，另用控制器验证车轮、步行接触和既有过街。先验选面不侵入同层车行面、建筑墙柱、水域和已知用途，比较包体与三角面数量，再考虑推广；样段通过不等于全城通过。
