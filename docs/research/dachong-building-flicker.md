# 铜鼓路建筑闪烁诊断

日期：2026-11-13。范围：用户截图所示铜鼓路、大冲国际中心附近。仅诊断与规划，未修复生产代码，未重建城市包。

## 结论与范围

已确认截图同一路段的一组普通楼存在共面重复墙体：大范围轮廓 `way/533679865` 与其内部 A–E 栋分别从地面挤出，在共享边界上同时生成不同立面的墙。D 栋的两个屏幕采样点命中两张距离相同、立面参数不同的墙；移动时容易出现深度争夺（z-fighting），表现为窗格破碎、条纹跳变。Three.js 官方对这种深度判定冲突的说明见 [Cameras](https://threejs.org/manual/pages/cameras.html)。

浏览器已用实际 W 输入在铜鼓路移动并拍摄对照。随后临时隐藏大范围轮廓的渲染三角形，两处射线重复命中均消失，目标区域的混合立面随之移除；操作最终恢复。此实验用于隔离问题，整栋隐藏不是修复方案。尚未对用户截图中的所有楼或整城闪烁逐一归因，也未完成修复后的连续移动验收。

## 代码原因

1. [buildings.py](../../tools/sz/buildings.py) 用 `building:part` 标记建立显式父子处理路径。本组对象均以普通 `building` 记录进入，因此不能由该分支解决重叠。
2. [buildingPlacement](../../js/sz-building-layout.js) 用地面标高加 `minHeight` 计算底部；本组均从地面起算。
3. [buildCityBlocks](../../js/sz-buildings.js) 分别对每个对象调用 `addWalls`，并分别给出立面、种子、楼高；本组未合并共面外墙。相邻网格批次保留了两套共面三角形。
4. [createBuildingMaterial](../../js/sz-materials.js) 使用固定种子生成窗灯，已有 `fwidth` 远景处理。本轮共面证据足以解释目标墙的混合纹理；没有证据把全部问题归因于逐帧随机灯光、LOD或抗锯齿。

## 修复计划

1. **固定输入和对象身份。** 接手先核当前代码、已载包和上述六个ID，保存哈希及同机位截图。检查这些对象是否已有后续修改。保持 OSM ID、原始轮廓、已有高度及来源，不把大范围轮廓直接删掉，也不凭名字判定父子关系。
2. **确定体量关系。** 对明确的包含、共边和重叠高度建立可审计的组合体量关系；若没有实际裙房证据，先把“重复墙面消除”与“真实裙房重建”分开。不能用 layer 推导绝对高度，不能因闪烁而改高或抬楼。
3. **生成唯一外表面。** 在共享墙段和实际重叠的高度区间只保留一套可见外墙，显式决定哪套立面负责该面并保留来源；非共边、露出的低层体量、院落和真实架空段保持。检查裙房顶面是否穿入塔楼，以及近景细节是否再次覆盖同面。显示、碰撞和可站立屋顶使用相同组合体量规则。
4. **适度推广。** 先处理该组并扫描现有包内同类“普通 building 内含普通 building”的共边候选。二维相交只生成候选；桥梁、独立连桥、屋盖和不同高度层不得自动合并。不先调整全局深度偏移或删减细节掩盖重叠。
5. **验收。** 几何回归涵盖完全共边、部分共边、跨渲染分块、不同底高、院落和合法架空。目标共享外墙在同一高度只有一个所有者；相关物理体量与屋面一致。铜鼓路用真实 W/S 和环视在蓝调/正午重复前进、后退及远近切换，记录连续画面；复查 A–E 栋及一个独立样区。只有仍残留细线闪烁时，另做窗格、楼板带、阴影的单变量对照。

按 `docs/25-FAST-CHECKS.md` 选择建筑及实际受影响检查；修改数据生成器才经 `build.py` 重建双包。此研究没有新增实现或将 T7 标为完成。
