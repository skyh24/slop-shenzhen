# 世界之窗附近深南大道的人行道侧别

佛山街、福清街附近的双幅路可以只保留靠街区的两条纵向步行带。建议先在佛山街附近已核对的双幅重叠区间，取消两幅车道朝向中央分隔带一侧的模拟铺装和环境行人路线。两侧外缘继续服务步行，横向过街设施按各自的来源和层级处理。向福清街延伸时逐段核对主路、辅路和分合流处。下文记录的是 2026-11-18 的调研结论，现场通行与修改后的场景效果待验。

## 中央两条带从哪里来

`buildSidewalkTracks` 对合格地面路段依次尝试左右两侧，默认沿路缘向外偏移 2.1 米，再依据地面、碰撞与车行范围筛选。因此两条独立主路线最多产生四条纵向候选。保留下来的轨道交给 `connectTracks` 生成转角连接，`buildPavementRibbons` 沿两者绘制默认宽 2.2 米的模拟铺装。环境行人也从活动区内的轨道选择出生位置并沿线行走。取消中央侧候选可以同时去掉该侧的铺装和沿线行人。[步行轨道与铺装](../../js/sz-pedestrian-tracks.js) · [行人活动区与出生](../../js/sz-pedestrians.js)

在上述经线断面，两幅主路的包内宽度均为 16 米。按现行偏移取四个模拟带中心点，朝内两点均落在 `深南大道-arterial-median` 草地三角面上，朝外两点均落在其外。这个局部几何检查复现了中央候选与绿带的重叠，不能据此认定整个区间每段都生成了行人。[当前城市包](../../js/sz-city.json.gz) · [横断面计算](../../js/sz-section-frame.js)

中央绿带由构建器根据同层、相向的两幅主路估算，并扣除车行范围、已有铺装、源步道等。运行时 `arterialMedianAt` 供路树过滤；行人装配已查询 `reserveWalk` 和 `plantingAt`，未直接查询该通用分隔带。绿色三角面上的禁走判断可能遗漏已裁掉的区域或路口端头。分隔带几何可辅助判断哪侧朝内，不能用来判定全部步行权限。[干道分隔带生成](../../tools/sz/arterial_corridors.py) · [分隔带查询](../../js/sz-road-frontage.js) · [树木接线](../../js/sz-scene-site.js) · [行人接线](../../js/main.js)

## 局部处理与验收

1. 用两幅主路的源 way、起止节点和实际平行重叠区间限定范围。沿每幅断面判断哪边对着另一幅，跳过该段内侧的纵向候选。源线局部反向、遇到匝道、辅路分合流、桥隧或配对不清时重新核对，避免整条深南大道统一删一侧。断面的 `side=1` 是源线左侧，`side=-1` 是右侧。[道路建图](../../tools/sz/roadgraph.py) · [断面侧别](../../js/sz-section-frame.js)
2. 保留外侧已有模拟带。后续接入两条独立步道时，由源线负责对应区间的铺装和行人轨道，一并移除重叠的外侧模拟段。路口逐处核实有来源的横向过街和同层等待面，天桥及接坡单独核实高度和连通。此次范围只涉及地面中央的纵向模拟步道与环境行人。[步道装配](../../js/main.js) · [道路与地面](../03-ROADS-GROUND.md)
3. 验收时从上方确认两侧铺装在正确的路缘，中央无纵向模拟铺装，再于街面观察外侧有人行走、中央无沿线出生或行走。检查两端转角连接、离开再返回触发的活动区重建，以及区外普通道路的原有行为。有源横向过街按自己的层级检查；静态画面只能验证外观，无法单独证明路网连通。[行人测试入口](../../tests/sz-pedestrians.test.cjs) · [验收标准](../10-PERF-QA.md)
