# 白石路与沙河西路桥板误碰撞调查

更新：2026-11-13。范围为调查与实施规划；没有修改运行代码、源数据或城市包。读取基线为 `bf7d59f` 及当时工作区，工作区有其他任务并行修改，实际文件哈希保存在本地 QA。

## 结论与证据边界

用户截图位于沙河西路接近白石路处。小地图黄色白石路的两条主线，在当前源路网中确实是桥：`way/25543384`、`way/231901256`，`bridge=true`、`layer=1`。沙河西路主线是 `layer=0`，两者平面交叉处没有共享路网节点；不能直接把它认定为可转向的普通十字路口。

另一方面，当前生成场景将该处桥顶与地面同时放在约 8 米。在这个已生成的同高场景中，不能仅因为表面属于桥就阻止车辆跨过。离线调用生产碰撞函数确认：地面采样的浮点误差会把齐平桥板误判成侧墙。这是确定存在的代码缺陷，但尚未通过正式页面的实际出租车与按键复现，不能断言它是截图阻挡的唯一原因。

用户明确的通行要求：桥面也是道路；没有实体护栏、没有真实台阶且路面连续的地方应能驶过。护栏必须按实际实体阻挡，不允许用整座桥的包围盒作为墙。若确为桥上桥下关系，则需保留不同标高与净空，不能通过开放横向转向掩盖结构问题。

## 已定位的问题

### 1. 齐平桥板被微小高度误差变成横向障碍

调用链：

- `js/sz-scene-site.js` 使用 `graphWithRoadStructures` 后的路网，并排除已由专项结构接管的边。
- `js/sz-elevated-roads.js` 的 `planLink` 从显示桥板生成 `elevated-slab`；本例桥顶 8 米，底部 7.35 米。
- `js/controllers.js` 的 `buildingContact` 使用 `y + body.bottom >= c.maxY` 排除桥顶以上接触，比较没有数值容差。对 `bridge-slab` 存在支撑相关处理，但本例是 `elevated-slab`。
- 当结果只比 8 米低一个浮点尾差，桥板仍被交给 `spanContactPolygon` 和 `polygonContact`，产生完整的横向推出。

在沙河西路北向主线 `way/557225631` 上，局部坐标约 `x=-10672.350001, z=1148.496127`：

| 输入 | 生产碰撞函数结果 |
| --- | --- |
| 地面/支撑高度 `7.999999999999999` 米 | 命中 `sz-elevated-road:4090` 的两块桥板，推出深度约 1.01956 米、0.60948 米 |
| 同位置高度 `8` 米 | 无桥板碰撞 |
| 同位置高度 `8.00000001` 米 | 无桥板碰撞 |

使用控制器默认车辆脚印（半宽 0.86 米、半长 2.18 米）及当前生产 `buildingContact` 函数。即使给该脚印标记桥面支撑，`elevated-slab` 仍命中。没有改生产函数以取得结果。

另外对四条源道路中心线按约 0.5 米间隔扫描：

| 道路 | 源 ID | 桥板碰撞采样点数 |
| --- | --- | ---: |
| 沙河西路北向主线 | `way/557225631` | 3 |
| 沙河西路南向主线的本地段 | `way/582188686` | 2 |
| 沙河西路东侧辅路 | `way/962816490` | 4 |
| 沙河西路西侧辅路的本地段 | `way/1467810804` | 3 |

这是局部几何/碰撞函数诊断，点数不是车辆卡住次数，不代表四条完整路线验收失败或全城扫描结果。截图的精确车道、车辆模型脚印及完整控制器状态还需实驾确认。

### 2. 桥梁的上下关系与场景标高不一致

`data/source/waterfront-samples.json` 为这组桥配置估计 `deckHeightM=8.0`、`girderDepthM=0.65`。`tools/sz/waterfront.py` 记录两端落地高度，运行时沿桥生成断面；它没有在这组道路交叉处建立跨越沙河西路所需的桥下净空约束。

局部采样得到桥顶 8 米、道路地面 8 米，桥底相对地面的净空为 -0.65 米。这里的负数表示桥板嵌在当前地面，不是实测现实净空。既有滨水测试检查两岸步道在白石路桥下的净空和桥端接地，并不等于沙河西路机动车穿越已验收。

这需要独立核查源拓扑、现场/街景及纵断面：若确为上下层，应生成连续引坡和有效净空；不能直接把 `layer=1` 当成固定的实测高度，也不能只抬一块桥面导致桥头断开。

### 3. 通用护栏开口仍需单独审计

`addBarriers` 会检查相邻桥面以留开口，普通地面道路并未作为所有已核实平交开口的统一输入；因此存在其它桥头/匝道的潜在封口风险。但本次主线复现命中的是桥板，并不是护栏，不能把删除护栏当成已经验证的修复。

## 通用修复计划

1. 先用当前出租车的真实碰撞脚印与接触状态复现，记录阻挡对象类型、来源、实际高度和推出量；同时检查路缘、护栏、桥板与车辆障碍。保留上述数值反例。
2. 在共用接触层修复数值误差。使用与米制精度相称的极小容差，并核对局部斜面高度和支撑身份。禁止扩大抬阶阈值、统一抬车、全局关闭桥板碰撞，或仅按包围盒最高点豁免整块坡桥。
3. 同高且可达的接缝允许连续通过；桥侧、桥底及真实高差仍有碰撞。桥板、护栏、路缘和桥墩按实体分开。若统一 `bridge-slab` / `elevated-slab` 的支撑规则，需覆盖对应全部消费者。
4. 将物理接触与路网连接区分：几何齐平不能自动新建合法转向；平面相交也不等于共享节点。对于有来源的同层连接，按完整车行走廊裁切护栏和路缘，并让显示与碰撞开口一致；异层交叉不裁出转弯口。
5. 单独修复白石路的结构纵断面。先核实上下关系，再用两端接地、连续坡度、桥厚、下层车行宽度与车辆净空共同约束。与现有大沙河步道、辅路和跨水桥段一并核对，估计值仍明确标记估计。
6. 对所有桥板与车行面的空间交叠做离线审计，分类输出：同层接缝数值误碰撞、上下层净空不足、无合法连接的平面相交、栏杆侵占合法通道；记录对象来源和审核状态，不能对所有交叉点一律开口。

## 验收与交付

- 单元/集成反例：`8-一个浮点尾差` 对齐平桥顶不侧碰；真实低于桥板顶面的侧撞、撞桥底、撞护栏仍有效；斜桥不能借全局最高点免碰撞。
- 使用真实车辆脚印做整段连续移动，覆盖主线双向、两侧辅路、桥头上下桥、适用的倒车与转向；步行与骑行抽查共享接触行为。
- 白石路桥上与沙河西路桥下如需分层，分别验证活动表面、净空、NPC 路线、小地图/导航身份；不能把车辆吸到错误桥层。
- 回归大沙河两岸桥下步道、车公庙合分流、后海大桥、后海二桥、一个正常平交口。局部通过只记局部验收。
- 数据变化通过 `tools/sz/build.py` 生成双包及报告；该目录当前有其他数据任务，执行者必须先协调唯一构建进程。
- 输出修复前后阻挡对象报告、连续驾驶证据、相关检查结果、未核实纵断面清单。先完成数值缺陷修复，不把缺少实测高程包装成真实结构已还原。
