# 性能与加载优化方案

2026-11-12；只做调研与规划，尚未实施优化。当前核对提交 `f7b372d`，正式包哈希与 [HANDOFF](HANDOFF.md) 一致。正式工作状态与实施范围在 [TASKS 的 T10 专项](TASKS.md#网站体积与启动专项)，性能门槛沿用 [10号](10-PERF-QA.md)，不另设宽松标准。

## 结论

先减少无消费者的运行数据和重复内存，再按实测优化启动编译与发布缓存。保留现有城市范围、建筑、地形、道路和视觉效果；本轮实施候选不依赖降低画质。约1900个预编译任务不等于1900个文件或独立GPU管线，不能靠减少进度条数字交付。

第一个优化worktree承担 **S0测量 → S1无损减负 → S3本地发布缓存验证**。编译等价复用仅在S0证明值得做时纳入S1；S2编码实验、S4画质/全城流式和浏览器SQLite留作后续，不混入第一批。各小项单独提交，可独立回退；最终交付前后实测表，不承诺未经测试的提速比例。

## 1. 已知成本与证据等级

MB均为十进制；静态文件量、网络传输、CPU耗时、JS堆和GPU资源分别统计。

| 项目 | 已知结果 | 对决策的意义 |
| --- | --- | --- |
| 城市包 | gzip 11,304,063字节；解压JSON 51,429,667字节 | 解压文件大小不是浏览器内存；数据传输已低于25MB预算，仍可减负 |
| 地表 | `terrainSurface`约27.08MB，占解压JSON 52.65% | 最大表达成本；优先共享解码，再考虑改变编码，不能直接删除 |
| 本地运行资源 | 约13.03MB；纽约3.32MB、武汉5.34MB | 相同口径排除CDN引擎/字体；深圳约3.93/2.44倍，不代表慢同样倍数 |
| 建筑记录 | 深圳76,024；纽约37,353；武汉23,819 | 深圳覆盖和几何更多；记录数不等于独立现实楼栋数 |
| 二进制对照 | SZC1 gzip比JSON gzip多33,406字节 | 换成二进制并不自动缩小或提速 |
| 编译进度 | `main.js::precompileShaders`统计应用jobs；部分job多次调用`compileAsync` | GPU唯一管线数若无可靠接口则未知；应量墙钟耗时和首次交互卡顿 |
| 真实运行性能 | 当前范围冷热启动、FPS、CPU、内存和显存尚无本轮实测 | 禁止把历史小范围成绩作为现状或承诺 |

静态比较沿用同期 [体积调查](RESEARCH.md#网站体积与启动成本核查2026-11-12)：深圳源码基线`3c72f66`，纽约`536a907`，武汉`7a62402`；本轮核对当前关键调用及包哈希，不重跑三城浏览器对比。

### 两个新候选

**运行包中的道路副本。** [decodeCityPayload](../js/sz-data-format.js)输出`geo.roadGraph`，没有输出顶层`raw.roads`；[sz-spatial](../js/sz-spatial.js)从路图建立道路。当前`CITY_PAYLOAD`正式消费者只取建筑立面枚举。顶层`roads`仍被[离线建筑测试](../tools/sz/tests/test_buildings_plan23.py)使用，须先审全部消费者、格式验证、报告和重打包路径，将审计所需数据保留在离线流程，不能直接删源文件或删测试保证。

本轮只在内存中移除顶层`roads`，用紧凑UTF-8 JSON、gzip level 9 / mtime 0重新压缩：基线可复现11,304,063字节，候选10,533,782字节，减少770,281字节（6.81%）。未写入正式包，未证明完整兼容，也未测启动时间；这是包体收益候选，不是已完成优化。

**地表重复解包。** [unpackSurface](../js/sz-ground-surface.js)每次校验并新建positions、indices、cellRanges的TypedArray；[地面](../js/sz-ground.js)、[空间查询](../js/sz-spatial.js)、[高架规划](../js/sz-elevated-roads.js)各有调用，隧道规划在选中对象时也会调用。当前三类数组合计5,878,980个数，单套4字节数组约23.52MB；并非所有副本同时常驻，实际收益须记录调用次数、独立ArrayBuffer、峰值和释放后内存。候选为同一载荷共享只读解包结果，查询状态独立，重试/换包不复用旧结果，渲染释放不能破坏接触查询。

## 2. 数据取舍与真实性

| 数据 | 策略 | 原因 |
| --- | --- | --- |
| 建筑足迹、内院、塔裙/部件、高度与`heightSource`、稳定ID | 保留，可字典化或无损编码 | 决定城市形态、可追溯性、碰撞与真实高度区别 |
| 地形、活动地表、山体、海岸、水岸 | 保留；先共享内存，后研究模板与例外面 | 地形与活动地表用途不同；不能为省体积压平山体、填洞或抹掉接缝 |
| 有向路网、桥隧层级、转向与接触面 | 保留，同源生成显示/导航/碰撞 | 空间相交不等于道路连通，上下层不能合并 |
| 地铁站/出口、地点名称、身份和搜索引用 | 保留核心索引；详情未来可分块 | 体积相对小，直接影响搜索和场所辨识 |
| 无运行消费者的道路副本、完整审核清单、中间报告 | 移出运行热路径，离线保留 | 对开发审计重要，不必每位访客下载或每次启动计算 |
| 远处招牌、窗格、空调、树冠细节、装饰阴影 | 保留现状；测得瓶颈后才调整LOD/创建范围 | 不等于无用数据；当前已有图集、实例化、LOD和卸载 |
| 原始影像、大型源文件、历史QA、参考项目 | 留在研究/构建环境，不纳入发布清单 | 供核验和再生成，不直接服务运行场景 |

后续真实感投入顺序建议：**可靠地面/道路标高与桥面连接 → 建筑部件和可核入口 → 路缘、人行道、铺装与绿地边界 → 立面/屋顶/首层外观 → 植被与人车行为**。当前8米城区地坪是派生面，不能因为压缩后文件更精细就宣称测绘准确；优化任务不顺带修订地理事实或加入新数据源。

## 3. 第一批实施设计

执行前检查新worktree的忽略文件：`data/raw/`、本地Python环境与锁定Three依赖不会随Git自动带入。按来源清单复用或准备所需输入，允许只读共享原始数据/引擎；可写缓存、输出包、报告和QA证据留在任务工作树，避免写回主工作区或两个执行者共用可写构建目录。缺输入时先完成不依赖重建的测量和候选，不凭空生成替代数据。

### S0：建立能解释原因的基线

复用现有QA，只补缺失的计时与计数。记录navigation→下载→应用解压→JSON解析→校验/解码→各场景组件构建→预编译→首帧→加载层隐藏→真实输入生效；并发阶段用时间线而非将子耗时相加。单列隧道审计、地表解包、材质/几何创建。

按组件记录job数、`compileAsync`调用数及墙钟耗时、共享代表对象覆盖率；记录原始TSL错误和着色器缓存状态。已知错误会干扰编译结论，须定位是否由本任务路径引起；相同错误基线也不能当作正式验收通过。

HAR包含引擎、字体、重试及预取。验证默认JSON和本机SZC1对照是否重复下载JSON。开发`serve.py`的no-store不能代表生产热缓存；使用独立本地发布服务做S3对照，避免同时改变配置与代码却归因不清。

### S1：逐项无损减负

1. **运行道路副本**：核全部消费者与源保留方式，在build.py内建立明确的运行/审计输出边界。两个正式包及报告仍同次生成，检查重建与`--repack-existing`兼容，不手改压缩包。若存在不可拆消费者，交明确证据并跳过该候选。
2. **共享地表解包**：每份有效载荷只创建一套只读数值数组，保留不同采样器的状态与索引语义。禁止双份载荷混用、共享数组被修改、重试泄漏或几何dispose误伤接触面。该项先保持包字节不变，单独量CPU/内存。
3. **启动审核移出**：核[main](../js/main.js)内`planSzTunnels(...).reviewList`的所有消费者；仅将无正常运行用途的审核计算放入离线或本机QA入口，审核能力及安全校验继续保留。该项保持包字节不变。
4. **条件编译优化**：仅当编译是主要等待项时，选一个实例组件核实等价管线并复用现有`sharesPipelineWith`。依据锁定r187的属性/节点/透明/阴影/MRT配置，不能按材质名字去重。不默认删预编译、提高并发池、吞错或把所有编译推迟到游玩时。

优先级可由S0的真实主瓶颈调整；每项单独对照、测试和提交。候选没有稳定收益或增加首次移动/转头/时段切换卡顿则回退该项，继续下一项，不把无效尝试留在默认路径。

### S3：发布资源与再次加载

保持开发服务器的no-store。增加独立本地发布清单/命令，只收正式入口可达资源、默认城市包及许可；不带raw、ref、QA、Git、测试、完整审计报告和实验SZC1，不改变原生模块方案。

优先使用HTTP版本缓存：完整版本目录包含代码与数据，相对import不能跨版本；静态版本资源长缓存，入口/版本清单可更新。资源齐全后切入口，旧版本保留回退；静态版本路径与内容哈希建立对应，缓存损坏或缺资源可恢复。文本采用gzip/Brotli，已有gzip城市包不二次压缩；响应头和浏览器实际解码须验证。

引擎/字体是否同源托管由HAR决定，保留版本和许可。首屏必须数据与场景先就绪；非关键字体或装饰延后仅在有证据时采用，不能提前隐藏加载层造成空城或输入无效。第一批不要求Service Worker或离线模式，不部署公网。

## 4. 压缩、分块与本地数据库的选择

| 方案 | 建议 | 触发条件与边界 |
| --- | --- | --- |
| 精简JSON + gzip / 文本Brotli | 第一批采用现有格式，先移出无消费者字段 | 同一载荷比较真实响应字节和解码成本；不重复压缩gzip文件 |
| 列式二进制、ID字典、整数/增量编码 | S2选一个候选实验 | 当前SZC1无体积优势；不以降低已有数值精度冒充无损 |
| 格网模板 + 裁切/工程例外三角面 | S2后续候选 | 最大字段值得研究；保持索引、绕向、孔洞、接缝与所有采样结果 |
| 全图轻索引 + 独立压缩空间块 | S4，第一批不做 | 当下载/内存仍超预算；概览、搜索、路网跨块连续，加载块不等于业务区域 |
| 构建端SQLite / GeoPackage | 可作为源融合和审计索引，非性能优化前置 | 仅在重复查询/增量维护有收益时引入；raw快照、来源哈希仍保留，build.py统一输出 |
| HTTP缓存；必要时Cache API | 当前优先HTTP，离线需求明确后再加Cache API | 缓存减少重复下载，不能代替解析/建模/GPU编译优化 |
| IndexedDB | 后续存结构化索引、用户状态和离线元信息 | 不默认把整城展开为海量逐条记录；设计版本、配额失败与清理恢复 |
| SQLite WASM + OPFS | 暂不采用 | 只有浏览器复杂离线SQL/编辑收益能抵消引擎、Worker、VFS与并发维护成本时重评 |

编码借鉴[CityJSON 2.0.2](https://www.cityjson.org/specs/2.0.2/)的scale/translate、共享顶点与几何模板，不做全格式迁移；整数化必须能还原当前精度。分块文件独立压缩；整城单个gzip不能直接获得任意块的随机读取能力。第一批不引入新的瓦片归档格式或运行时依赖。

[Cache API](https://developer.mozilla.org/en-US/docs/Web/API/Cache)保存Request/Response，由应用管理版本与删除，不自动遵循HTTP缓存头。浏览器持久化不能视作永不丢失的数据源；允许清理后重取。[SQLite持久化文档](https://sqlite.org/wasm/doc/tip/persistence.md)列有不同OPFS VFS与并发/响应头要求，不能笼统认为所有OPFS方案都必须COOP/COEP，也不能把本地数据库当成GPU优化。

## 5. 验收与停止条件

性能协议以10号为准：同一M1 Pro级设备、实际输出2560×1440、前台聚焦、相同相机/时段/种子/人数与画质；记录浏览器、DPR、pixelRatio、缩放和引擎。HTTP冷/热各至少5次，分别列逐次、P50/P95/最差；HTTP缓存与着色器缓存状态分开。开发与发布配置各自比较，不交叉冒充同条件收益。

| 交付证据 | 验收 |
| --- | --- |
| 启动 | 冷启动预算≤15秒；首帧、加载层隐藏、真实输入生效三项同时满足；不能只报进度条消失 |
| 帧时间 | 地面≥60FPS、飞行≥50FPS；出生区/CBD/夜景/飞行每段≥60秒，列帧间隔P50/P95；首次移动/转头/切时段尖峰另列 |
| 绘制与内存 | draw calls≤1500、三角≤600万；记录P50/P95/最大；JS堆、RSS、数组字节和资源计数分开，总VRAM不可可靠测则标未测，不用计数伪造≤1.5GB |
| 数据 | 报压缩包/整站完整首访字节；保留对象ID、heightSource、精度、路网拓扑和全部实际几何，仅审计字段迁出须有显式允许差异清单 |
| 画面与接触 | 相同机位昼夜截图；四模式、真实步行/驾驶、接缝、桥上/桥下与安全切换；保持既有1mm边界/静止2cm接触标准 |
| 缓存与失败恢复 | 首访、热访、新版本、旧版回退、缺资源、坏gzip、重试；不得出现代码数据混版或双画布 |
| 长时运行 | ≥20分钟跨块往返，同地点比较保留资源；无新增泄漏、设备丢失、输入失效或死锁 |

共享地表/格式/入口变更运行`full`；纯发布工具按tooling及实际消费者；不为每项重复跑全套20分钟，阶段定向检查后对最终版本做一次完整性能对照。失败修复后重跑受影响范围，引用结果须符合25号复用条件。所有原始证据放本地`docs/qa/site-cost/`，不提交。

最终表必须有：基线/最终提交、包哈希、环境、每项改动、指标前后值、变化量、已知误差、画面/行为验证、采用/撤回及剩余瓶颈。时间收益须超出基线波动；接近波动时增加必要样本或标无法判断，不能仅凭均值下降声称有效。

完成第一批不等于全城验收或发布。既有TSL错误未解决、目标设备缺失或显存未测均如实列出；不得以未测指标宣称预算全通过。后续只依据剩余瓶颈选择S2或S4，避免同时重写格式、Worker、流式和画质系统。
