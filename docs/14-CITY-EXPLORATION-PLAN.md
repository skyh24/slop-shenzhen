# 14 城市探索、地铁透视与重点区域体验规划

日期：2026-11-09。状态：后续计划，未实施或验收。本文件汇总用户新增体验要求，供主线程在当前地面修复与数据样区验证后分批执行；不要求中断正在进行的P0修复。

## 1. 目标与现有计划的关系

城市不仅能远看地标，还应能搜索具体写字楼、小区和场地，点选整片区域，查看模拟地铁与车流，再选择驾驶、步行、骑车或飞行进入探索。重点景区保留可辨认的真实建筑、雕塑、绿道与活动空间；普通建筑形成稳定、可信的街区背景。

本文件补充以下要求：

- 地图内选择地铁线路，进入沿线透视视图，模拟车站与列车行驶；明确不是实时运营。
- 高亮主干道，查看沿真实道路运行的模拟车流。
- 精细还原南头、华侨城、世界之窗、欢乐谷、人才公园、深圳湾、莲花山、南山公园，以及万象天地、万象城、海上世界、欢乐海岸、深业上城等区域。
- 球场和高尔夫场地独立识别；玻璃写字楼、高层住宅使用有来源的通用建模体系。
- 搜索或点选区域后，区域整体适度提亮，地图边界加亮；点选楼栋、小区、场地可显示名称。
- 地图选择起点与终点自动驾驶；步行和自行车可沿真实开放路径探索景点。
- 点汽车入口后，到最近可用道路边上车；下车时靠边停车并落到可站立位置。
- 点飞机入口后，在人物旁的合适位置出现四旋翼载人飞行器，1秒快捷升空；降落使用1秒快捷转场落到核验过的平地。

继续遵守[12号街区规划](12-URBAN-FABRIC-PLAN.md)、[13号数据样区计划](13-DATA-DETAIL-PILOT.md)和[网站优化计划](13-WEBSITE-OPTIMIZATION-PLAN.md)。新数据不等于已接入；已有地标不等于整片区域已完成。全文地点均为用户指定待办，具体边界、对象身份、开放状态与设施现状须核实。

### 1.1 冲突时采用本次明确的新交互

- 普通搜索和点选先选中、显示名称及区域，不直接传送。09号文档早期“点一下地标就传送”在这些入口被本计划替代；传送保留为单独、明确的动作。
- 点击汽车/飞机模式入口按本计划执行快捷上下交通工具。09号中“不暗中传送”继续适用于普通选点和路线开始；用户主动点击快捷上车/起降是明确的转场动作，界面提示落点，不再附加一次重复确认。
- 1秒起降是游戏快捷体验，不声称符合真实飞行速度、航路或实际起降许可；与公开来源的物流无人机航线严格分开。
- 保留纽约原有整体布局、既有ID和1/2/3/4、M、V等入口；新增面板放入地图与相关模式。所有入口调用统一状态切换，快捷键不能绕过落点和乘员检查。
- 玩家飞行器沿用用户要求的四螺旋桨程序化模型。本计划不要求照搬08号早期“共轴8桨”的外形草案。

## 2. 统一地点系统：每栋楼、每个小区和场地可被选中

### 2.1 对象类型与关系

| 对象类型 | 标记与搜索单位 | 与区域的关系 |
| --- | --- | --- |
| 写字楼、住宅楼、其他普通楼 | 每栋独立楼体；真实楼名、栋号和别名有来源才显示 | 可以属于园区、小区、商业综合体；塔楼与裙房部件不重复伪装成多个地点 |
| 小区、办公园区、商业综合体 | 整体区域加内部楼栋 | 搜索小区名选中整体，搜索楼名/栋号选中该栋；保留多个出入口 |
| 公园、古城、景区、游乐场 | 独立管理区域或经核实的空间范围 | 内含步道、设施、标志建筑、雕塑、场地和观景点 |
| 球场、高尔夫、广场等场地 | 真实场地面与入口 | 可以在公园内、屋顶或独立地块，不因二维相交认作地面设施 |
| 道路、地铁线路及车站 | 道路路段集合、线路服务模式、站点实体 | 与附近地点建立有证据的入口/可达关系；不用直线最近距离代替实际连通 |

为所有已导入楼栋、组团和场地建立可选择身份。名称覆盖与对象覆盖分别统计：真实名称未知时显示“未命名建筑”“未命名场地”及已知片区/附近道路，不编造楼名、栋号或用途。用途未知的楼不能自动叫“写字楼”。

### 2.2 来源、标记与名称

- 优先复用源对象ID、名称、别名、地址、真实栋号和父子关系；城市更新前后名称保留版本与别名，不把已拆除旧建筑当成同一当前实体。
- 每个对象有选择几何、标签锚点、导航入口、来源和覆盖状态。标签锚点不是导航终点；建筑中心或屋顶不能直接作为步行/驾车落点。
- 面对象标签优先使用落在有效面内的代表点，避免凹多边形中心落在外面、湖中或内院。立体标签根据实际模型锚定，避开与邻楼标签叠压。
- 点击地图标记、区域面、三维楼体或场地时，显示其名称浮签与详情卡，使用同一身份。实例化/合批后保留拾取到源对象的映射，不能用整批网格的包围盒代替单栋选择。
- 名称浮签显示在选中对象上方或合适锚点；被遮挡时采用引线或边缘提示，不把标签误放到邻楼上。重复点击保持选择，不反复创建标签。
- 远景只显示重要地点或聚合标记；放大后显示楼栋/场地；选中对象名称始终优先。所有对象有标记能力不等于全城标签同时常驻。
- 字号、名称对比度、触屏点击范围与键盘焦点需可用；标签、路线和按钮相互避让。

### 2.3 搜索行为

支持中文全称、常用简称、已核实别名、拼音/首字母以及组合查询，例如“小区名＋栋号”。索引离线生成，搜索不要求先加载全城精细网格。

1. 输入查询，按名称匹配、当前视野/距离和对象类型排序；不把距离优先到覆盖准确名称匹配。
2. 同名结果显示行政片区、类型与上级区域，用户可区分多个“万象城”等对象；不能默认把一个名字套给所有同名商业体。
3. 选择结果后，地图定位到对象、名称浮签出现、对应区域/楼栋高亮；玩家位置与模式保持不变。
4. 详情卡提供“查看区域”“步行”“骑行”“驾车”“前往”等实际可用动作；数据缺口用简短状态说明，不显示无法执行的假按钮。
5. 没有命名数据时可按类型与附近位置发现对象；不保证能搜到数据库没有的真实楼名。没有结果时明确无匹配，不能编一个地点。
6. 请求较慢时保留当前选中态并提示加载；连续搜索以最后一次选择为准，过期请求不能把镜头拉回旧地点。

## 3. 点选后的区域提亮与边界高亮

地图与三维场景共享 `selectedFeatureId`，临时悬停、已选中、导航起终点、地铁/道路图层分别管理，避免颜色和状态混在一起。字段名为接口建议，实施时适配现有模块。

- 地图：选中区域加清楚的描边与低透明度填充；选中单栋只描该栋，选中小区/景区描整体边界。多面、岛状区域、内洞保留，不用矩形包围盒代替真实范围。
- 三维：区域内已绑定对象适度提亮，可用低强度覆盖或轮廓效果，保留玻璃、石材、植被和夜景材质差异；不直接永久修改共享材质，使其他区域一起变亮。
- 无可靠区域边界时，仅高亮已知对象并说明范围未完整，不生成假圆圈当真实边界。
- 道路和地铁使用各自线形高亮；所选区域边线不能覆盖线路色与导航线，采用描边层级和明暗区分。
- 嵌套对象先选择最明确的命中对象，详情卡可“查看所属小区/园区”；重叠地块和屋顶场地按对象类型、表面层级消歧。
- 点击空白处或按退出键取消选择，恢复原材质；面板关闭、切换时间和卸载重载后不能残留高亮。
- 边界和整体提亮是选择反馈，不是会移动玩家的传送预告；地图定位与玩家定位明确分开。

## 4. 地铁：线路查看与模拟透视

### 4.1 使用流程

1. 打开地图，在地铁图层选择一条线路，显示线路、车站与已核实出入口；首次默认不显示，沿用已有选择持久化。
2. 点击线路或站点，在同一面板选择“模拟透视”。提供沿线斜俯视、跟随列车和聚焦车站三种视角，首轮优先做斜俯视与跟随。
3. 进入后常驻简短“模拟运行”标识，显示线路、方向、当前/下一站；可播放、暂停、重置和调整模拟速度。
4. 点击任一车站聚焦站体与进出站列车，再切回全线；可显示换乘关系，但未核实的站内通道不生成假走廊。
5. 退出透视恢复原世界相机、玩家模式和正常地表显示，不把玩家掉入地下，不中断并发的安全状态处理。

### 4.2 数据和空间层次

- 以项目已筛选的深圳地铁网络及线路成员、车站、出入口关系为底座。上下行、支线和服务模式不能被计成不同物理线路；真实线路色另核官方来源。
- 区分地面、高架、地下区间；真实三维标高有依据才使用。车站位置与出入口位置分开，不把入口点当作站台中心。
- 缺地下深度时，采用独立的示意剖层/纵向展开视图，并明确“深度示意”。保留真实平面走向与站序，示意深度不写入地理高程或地面碰撞。
- 缺平面线路或站间连接时只显示已知部分和缺口，不能拿站点直线连成“真实隧道”。仅站序可用时可提供明确的线路示意图，不伪装空间透视实景。
- 站型、岛式/侧式站台、编组、屏蔽门和列车外形逐线核实。缺资料用简化示意站体与列车，并区分实景还原程度；不把所有站都当同一种标准站台。
- 透视通过局部裁切、地表淡化或独立观察场景实现。优先只处理所选线路走廊，避免全城透明造成排序错误、过度绘制和视觉混乱。
- 观察视图和可驾驶/可步行世界分离；首版不等同于新增可进入地下站厅、购票、乘车或地下角色玩法。

### 4.3 模拟运行

- 使用可复现模拟时钟，按线路长度、站序、方向与设定速度生成运动；加速、巡航、减速、停车、开关门形成完整循环。
- 发车间隔、停站时间和速度是模拟配置，有公开运行资料时可校准但不宣称实时列车、实时到站或实时客流。
- 列车沿实际曲线按弧长前进，车厢随曲线分段对齐；两方向占不同已知轨道/示意轨道，不重叠对穿。
- 站台停车位置、编组长度和车门演示保持一致；终点有证据的折返设施按来源表示，没有时采用明确的模拟重置，不穿越站台掉头。
- 相邻列车保持间隔；暂停冻结本视图列车与时钟，快进不造成错过停车或一帧跨站。地铁模拟倍率不自动修改世界车辆/信号时钟。
- 首轮只运行一个已核实连续区间与两个方向，完成数站停靠再扩全线；离开透视后回收模型和监听，不让所有线路后台满规模模拟。

## 5. 主干道高亮与模拟车流

候选包括用户强调的深南大道、北环，以及经核实的滨海/滨河等主干路。具体范围与道路命名以源对象核实，不在此认定每条路所有分支都属于同一主线。

- 地图提供主干道列表，搜索道路或点线可选中连续路段；用源路段集合组织主线、辅路和匝道，不能只按相同名称全城合并。
- 高亮保留道路层级与断点；查看立交时提供主线/匝道区分，二维相交不变成可转弯路口。
- 车流显示“模拟车流”；同一位置的地图车点与三维车辆来自同一模拟状态。远处可用明确的简化流动表示，但不与近景实体双算、不同步。
- 可切换低/中/高模拟密度观察，人数/车数受有效车道容量与性能池限制；不把档位写成实时拥堵指数。
- 主线、辅路、匝道及路口遵守实际方向、车道和转向约束；沿用两组绿3秒、黄1秒、红4秒模拟配时，不称真实信号方案。
- 道路卡片可设置起点/终点和聚焦街景。选中整条主干道不自动为玩家规划一条跨越所有分支的路线。

| 南头古城 | 街巷尺度、历史建筑、门楼、沿街立面、广场和有来源的雕塑/装置 | 主入口到核心街巷，窄巷避让、结伴、店前停留；骑行权限另核 |

### 6.1 每处统一交付

每个区域建立区域卡：真实名称和别名、源ID和边界、入口、父子对象、资料日期、图纸/实景、已建/在建/设计状态、步行/骑行规则、标志建筑/雕塑清单、已知差异。

建模顺序是边界与地貌→主要体量→入口/步道/绿道→标志建筑与雕塑→树木街具→人群→日夜材质。地标、雕塑全部程序化建模；近景保留决定轮廓的构件，不能用通用柱体代替有辨识度的雕塑。资料不足先保留简化及缺口，不凭空补公共艺术名称或位置。

区域建成不能只拍一张主楼图：至少有入口地面视角、内部主路径、区域斜俯视、标志物近景和夜景。主路径需实际走通，场所出入口及边界与地图高亮一致。

### 6.2 普通玻璃办公楼和高层住宅

- 玻璃写字楼：真实足迹和塔裙体量优先，窗墙比、幕墙分格、首层大厅、退台、屋顶设备层依据来源选型；玻璃色、粗糙度和窗灯避免全城同色同节奏。
- 高层住宅：保留板楼/塔楼平面、组团朝向、栋间距、阳台/窗带、屋顶形态与底层入口；已知层数与显示窗行分开，不能为整齐窗格改楼高。
- 其他老住宅、别墅与城中村继续按12号分类；未核用途保留中性外观，不由高度一项决定用途。
- 普通楼不要求全部单栋手工精雕；每栋都保留可选择ID、来源、名称和位置。重点视线邻楼可有单栋覆盖，其他按真实类别和固定种子生成。
- 小区必须有整体关系，不能只有楼栋没有入口、围墙开口、内部道路和绿地；源资料不足不自动补一套假小区总图。

## 7. 模拟人流、绿道和景点可达

- 地点入口、步道节点、观景点、商店前场和场地入口构成活动网络。先有可站立/可走的路径，再生成角色；密度与停留时间是模拟参数。
- 人群按场景表现散步、跑步、结伴、排队、观景和场地活动；人数受路径宽度、节点容量和对象池共同限制，不在全城同时满密度。
- 年代与植被成熟度分别记录，新增景区不统一刷小树，老公园也不全部刷大树；树冠与路径净空一起验收。
- 步行可走合法人行道、台阶、广场及景区步道。骑行只走有依据允许的道路和绿道；遇台阶/禁骑段提供绕行或明确的“下车步行”，不直接骑车穿过。
- 暂无权限资料的园区内部骑行不默认为允许。可观察不等于可以穿越围栏，详情卡把“查看”与“进入探索”区分。
- 已知入口和道路之间必须有真实连接；景点中心点、水体中点、屋顶或山顶不能充当所有移动方式的通用终点。
- 首版提供路径显示和手动步行/骑行；后续可加明确启动的路线跟随，沿同一网络运行、随时手动接管，不把选中景点自动变成强制移动。

## 8. 起终点导航与汽车上下车

### 8.1 地图路线

1. “规划路线”中选择驾车/步行/骑行；驾车复用现有自动驾驶，其他方式先做正确路线与手动探索。
2. 起点默认当前有效位置，也可明确点选另一起点；终点可点地图或选择楼栋/区域。页面显示吸附后的实际入口/路边停靠点，不静默把目标移到道路另一层。
3. 路线依据移动方式计算：单行、转向、信号、车身转弯、桥隧表面及权限共同约束；步行/自行车不复用机动车图当万能图。
4. 玩家不在所选起点时，提供“前往起点”明确动作，再开始驾驶。普通选起点不移动角色。
5. 驾车到场所附近可用停靠点结束，标出到入口的剩余步行段；不能把车开到商场屋顶或公园湖心。
6. 路线缺口、未知桥高、禁行或目标不可达时说明原因和已知可达入口；不得用直线、隐式瞬移补一段导航。

### 8.2 点击汽车入口：最近道路边上车

“点车”统一支持模式按钮/快捷键；三维里明确标识的玩家可用车也可进入同一流程，点击普通环境车辆只查看，不默认劫持或替换任意NPC车辆。

1. 以人物当前可站立表面为起点，寻找最近可用道路边停靠位置。按可达关系和距离排序，排除桥上桥下错层、护栏外、高速主车道、路口、斑马线、公交站口和正在占用的位置。
2. 显示短暂落点标记与“前往附近路边上车”的状态，不要求重复确认；按用户快捷要求把人物转到已校验的停靠点并进入玩家车辆。
3. 角色绑定座位，第三人称可见合理坐姿；车辆停在正确方向，车轮接触同一道路表面，加入车流时先让行。
4. 当前道路不可用时扩大到配置范围内的下一候选；无候选就保持原位置和模式，提示附近暂无可上车位置。不能落到机动车道中央或未知高度面。
5. 被围墙隔开的最近道路若没有已核实连接，不直接穿墙切换；可明确使用用户选择的“前往起点”转场，但不把它当作实走路线。

### 8.3 下车：先靠边停稳，再站到路侧

- 行驶中点步行/下车后进入靠边流程，寻找当前可达的最近停靠点，减速停车后将角色放在有净空的路侧步行面；不是高速行驶中原地弹出人物。
- 禁停路段、桥隧或无路侧空间时驶向最近可用出口/停靠点；用户可取消或手动接管。找不到时保持乘坐并给出简短原因。
- 停车位置与下车站立点分别检查车身、开门侧空间、行人车辆、路缘、栏杆和水面，必要时换另一侧；不能把车停进人行道或绿化带。
- 下车后保留玩家车辆供再次上车；远离后按有界资源策略回收，不在眼前消失。重复切换不生成无限车辆或重复玩家。
- 用户要求直接路边停靠作为体验目标；不额外加入停车收费、泊车小游戏等未请求流程。

## 9. 自行车切换与景点探索

- 在允许骑行且有净空的表面生成或选取玩家共享单车，人物上车姿态与脚踏一致；不能在台阶、水面、悬空连桥或禁骑区域强行骑上。
- 在步行景点中点骑行，优先提示最近可用骑行入口；用户明确选择后才转场，普通模式点击失败不把人物送到远处。
- 下车时停稳并站在路径侧边，车辆摆放不堵入口、盲道或通行线；需要推行的区段可以首版降为步行并保留自行车状态，推行动画后续单独验收。
- 路线中出现权限变化、台阶、窄门或未加载地面时提前停下，不让自动跟随穿越。

## 10. 飞行器出现、1秒升空与1秒落地

### 10.1 快捷起飞

1. 点击飞机模式或快捷键4后，先在人物旁查找能容纳机身、起落架和旋翼扫掠范围的空地；检查顶部净空与起飞路径，不能在树下、楼内、桥底直接穿出。
2. 检查完成后在该处出现四旋翼载人飞行器，人物进入可见座位；模型和乘员就绪后进入1秒起飞过渡，结束切换到正常飞行控制和跟随相机。
3. 起飞终点为附近已核验无障碍的低空悬停位置，具体相对高度属于体验配置，不是道路/地形测量值。不能把“1秒升空”自动解释成1秒冲到全城巡航高度。
4. 人物旁没有合适位置时不穿模硬生成，保持当前位置并提示可用空地；提供明确的最近可用点动作。屋顶与高架需单独确认，不冒充地面起降点。

### 10.2 快捷降落

1. 点击降落后，寻找当前附近已加载、坡度适合、连续足够大的地面；排除水面、树冠、建筑屋顶误采样、行车道、人群、陡坡和未知地面。可给出候选落点，玩家也可明确选择一个已核验点。
2. 低空且路径清楚时，用1秒受控过渡降落；持续碰撞检查并预留落点空间，不能只检查起终点。
3. 从高空或绕障距离较长时，1秒采用明确的淡出/淡入快捷转场，直接到已核验落点，不播放穿过楼体或地面的超高速直线动画。这是游戏转场，不计为真实飞行轨迹或速度。
4. 落地后起落架接触有效表面，旋翼减速，人物在有净空一侧下机并恢复步行；若玩家选择保持乘坐则维持地面座舱状态。
5. 无合适落点时继续悬停、保留当前状态并提示，不把高度归零，不向最近DSM采样点强制落地。

### 10.3 时长、输入和失败恢复

- 1秒指模型/目标地面已就绪后的过渡时长；数据加载另显示等待，不能为了凑1秒进入未加载空间。起飞或降落用独立的过渡计时，不受地铁倍速影响。
- 正常活动页面中，以1000毫秒为目标，用真实时间推进而非固定帧数；测试不同帧率，不要求浏览器后台冻结时仍在墙钟1秒完成。
- 过渡中只允许取消等明确输入，重复点击不重复生成；异常取消回到最近稳定状态，不留下半绑定乘员或两个载具。
- 降低动态效果设置可用淡入淡出代替快速相机位移，完成同一状态结果。
- 玩家便捷起降点属于游戏功能，不在地图标成真实运营起降场，更不能自动加入配送航线。

## 11. 状态、模块与数据接口

沿现有原生ES Module架构分工，名称仅为建议；先检查现有模块，避免重复建系统。

| 职责 | 输入与输出 | 关键约束 |
| --- | --- | --- |
| 地点索引 | 源对象、名称/别名、父子关系、边界、入口→搜索与选中对象 | 所有合批对象仍能追到源ID；搜索索引不依赖精细网格全量加载 |
| 选择与高亮 | 统一选中身份→地图边界、三维提亮、名称浮签与详情卡 | 不改共享材质永久值；悬停、选择、导航分别管理 |
| 路径服务 | 移动方式、入口/路侧候选、有向图、表面版本→路线或具体不可达原因 | 不同模式使用对应网络，跨层不串连 |
| 模式切换 | 人物/车辆状态、目标点、净空→可取消的上下车/起降事务 | 就绪后一次性提交状态；失败保留原稳定状态 |
| 地铁观察 | 真实线路站序、来源属性、模拟参数→车站/列车及观察相机 | 示意深度与地理高程隔离；退出恢复原状态 |
| 区域细节 | 区域卡、楼体/雕塑/绿化/设施→分级细节与模拟人群 | 程序化、固定种子、来源和碰撞一致，按范围加载 |

地面交通状态建议覆盖：步行、准备上车、乘坐/驾驶、自动驾驶、靠边停车、下车；自行车对应骑行/停稳/下车；飞行器对应准备登机、起飞过渡、飞行、降落准备、降落过渡、地面乘坐/下机。地图选中和地铁观察是独立UI状态，不直接改变玩家移动状态。

共享规则：一个玩家角色、一个当前控制对象、统一表面身份；缓存或分块版本变化要重新验证落点。显示、人物接触、车轮接触和导航用同一几何。创建/取消/卸载明确回收模型、材质、监听和模拟任务。

## 12. 实施批次与验收

优先级保持：地面与接触P0、13号小范围数据验证在前。本计划按批次上线，不能把区域清单一次性全部建成通用盒子后称完成。

| 批次 | 最小交付 | 通过标准 |
| --- | --- | --- |
| F1 地点与选择 | 一个写字楼、一个住宅小区及其楼栋、一个公园/场地的搜索/点击/名称/边界 | 搜索、地图、三维点选同一对象；同名消歧；未知名称不编造；取消恢复原画面 |
| F2 主干道与路线 | 深南、北环已有样段的高亮和模拟车流，起终点及入口/路侧终点 | 路线实际可达；地图车点与实体一致；断线/跨层/不可达有明确处理 |
| F3 上下交通工具 | 路侧上车、靠边下车、自行车切换、飞机1秒快捷起降 | 同一乘员、无重复实体；停车/落点和整段过渡不穿模；失败状态可恢复 |
| F4 地铁透视 | 一段有来源的连续线路、多个车站与双向列车 | 停站、暂停/倍速、跟随/聚焦、退出恢复正常；非实时标识明确；未知深度用示意 |
| F5 区域样板 | 优先复用深业上城、人才公园/深圳湾，再选南头或万象天地一处 | 入口到内部连续路径、标志物、名称、边界、人流与日夜对照齐全 |
| F6 扩展区域 | 逐处扩游乐场、华侨城、山地公园、商业区、球场/高尔夫 | 每处独立资料和五级状态；需要扩图先补数据，不复制其他地点替代 |

### 12.1 必测操作

- 搜索精确楼名、小区名＋栋号、别名、同名项目、无结果；点选楼栋/区域/场地以及从楼栋切到所属小区。
- 从俯视到街面反复选择、取消、昼夜切换与跨块加载，检查名称定位、边界洞、材质恢复与遮挡。
- 地铁选择线路/站点，完整观看进站—停车—开门—关门—出站；暂停、快进、切方向、切相机、退出，不让列车穿站或重叠。
- 主干道高亮同时开地铁与区域选择，路线和线色仍清楚；低/高模拟密度运行至少5分钟，验证队列可恢复。
- 地图选点驾车到景点附近，靠边停车下车，再走到真实入口；手动输入接管，导航失败不瞬移补齐。
- 公园步行/骑车，遇台阶、禁骑、窄路及不连通点正确停下或绕行；山坡脚部与自行车轮接触一致。
- 平地、楼边、树下、桥下、屋顶和无数据边界分别测试汽车/飞机模式切换；无可用点时人物位置不变。
- 飞机起飞/降落过渡在30/60帧及低帧率下完成，复测高空快捷落地、取消、连点、目标被占用、加载失败和页面隐藏恢复。
- 乘员近景检查坐姿、手脚空间、座舱玻璃和上下车位置；不得在原地留下另一个玩家。
- 连续探索至少20分钟、重复相同区域3轮，检查模型/监听/缓存不持续增长；恢复普通游玩状态。

### 12.2 记录与预算

实施时建议保存到 `docs/qa/city-exploration/`，按批次分目录：来源卡、对象ID、路线、实际输入、截图/短录像、模拟参数、五级完成状态、性能与未解决项。自动跟随、快捷转场、实际步行分别标注，不相互充当验收证据。

沿用[10号性能预算](10-PERF-QA.md)，同设备、分辨率、时间与人数配置记录冷启动、帧时P50/P95、绘制调用、三角数和资源占用。标签按缩放与视野筛选，雕塑/建筑细节分级，地铁只加载观察区间，人车按近远区更新；不能通过删除必要碰撞或压平真实地形换帧率。
