## 2. 校验结果与真实性边界

`tools/sz/build.py --repack-existing` 先执行以下检查，再写快读候选包：

- 六份核心原始文件（OSM、Overture、两份 GloBFP、两份 Copernicus）的大小和 SHA-256 与清单相符。
- 复用浏览器的数据契约校验；核对建筑来源枚举、楼高、架空高度、坐标流、道路引用。
- 检查重复的源 ID＋几何＋垂直区间，检查地形三角索引和有限数值。多面对象拆分后允许共享源 ID。
- 审计量化后的建筑轮廓，以及高度/最小外接矩形短边超过 12 的候选。异常只列待核项，不按比例直接删除真实楼。

当前 36,064 条楼体、534 个地形分块通过编码契约；发现 **3 条量化后无效轮廓、299 条高宽比候选**。完整 ID 清单和各来源高度计数在 `data/source/data-validation-report.json`。其中 `encodingValidation=passed` 只表示可无损编码；`realityValidation=incomplete` 明确表示现状真实性尚未全部核实。道路占用、天空之城范围内遗留轮廓及 `globfp-overlap` 错配仍需按 23 号计划修复，本次不宣称这些问题已经消失。

## 3. 快速格式

产物：`js/sz-city.szc.gz`，由 `tools/sz/build.py` 生成。原 `js/sz-city.json.gz` 保留且本轮内容不变。

SZC1 使用小端、8 字节对齐的数值列和 JSON 元数据。48 字节头包含魔数、容器版本、元数据长度、数值区长度及 SHA-256；校验覆盖头部字段和全部内容。大整数列按无损范围选择 U8/U16/U32/I32，浮点列为 Float64，**不额外量化坐标和高度**。保留所有源 ID、名称、枚举、内院、架空高度和地形裁切。

浏览器先检查长度、版本、校验和、列边界及目标路径。地形列直接作为 TypedArray 视图；其他字段恢复普通数组，继续调用原有解码器。坏包走现有启动错误提示，不静默回退旧数据。兼容服务器已解压和仍为 gzip 的响应。

本机候选入口：`http://127.0.0.1:8080/?qa=1&data=szc`。普通入口仍用 JSON。候选入口是验证路径，HTML 原有预加载会同时请求 JSON，因此不能把它的整页流量当作正式迁移收益。只有来源复核和完整场景验收完成后，才应统一默认加载与预加载地址。

| 压缩字节数 | 6,916,984 | 6,754,700 |

全量 Node 测试 **451 项通过、0 跳过**；Python **104 项通过**。新增回归覆盖完整值往返、所有地形分块的显示顶点/三角索引/单元索引一致、跨块接触采样一致、损坏/截断/越界/非法路径/NaN/未对齐输入，以及原始文件同长度篡改。浏览器整场景状态另见交接，不能用这些数据测试代替道路实走。

整场景尝试：快读包已成功请求、校验并解码为地形数值视图，场景进入着色器编译，但本轮停在 44/819，未观察到第一帧；捕获的页面异常列表为空。恢复普通根地址、原 JSON 包后，对照也未完成图形引擎启动，未确定根因。因而只确认 **L2 生成、数据适配与场景构建阶段已运行**，不记 L4 画面通过或 L5 实走通过，不把启动问题归因于格式，也不宣称与格式无关。现场记录在 `docs/qa/fast-data/scene-validation.json`。普通入口未切换，浏览器测试页恢复根地址后关闭。
